# יחידה 8 — שוויון ואינדוקציה

<div dir="rtl">

**מטרה:** שוויון כעיקרון לוגי (כל דבר שווה לעצמו, ומותר להחליף שווה בשווה; מהם נובעות הסימטריה והטרנזיטיביות), והוכחה באינדוקציה על המספרים הטבעיים: בסיס, צעד והנחת האינדוקציה. הסטודנט מבין למה צריך גם בסיס וגם צעד, ומבחין בין מה שנכון לפי ההגדרה לבין מה שדורש הוכחה. היחידה בנויה לפי Logic and Proof (פרק 17) ולפי Natural Number Game, ושני העקרונות של השוויון הם הכללים =I ו־=E של forall x (פרק 39).

## המהלכים

בטבלה המהלכים החדשים כפי שהם נקראים אחרי שהם במקומם, עם דוגמאות מהשלבים; בסוגריים המרובעים מה שבוחרים מהרשימה.

| מהלך (כשהוא במקומו) | Lean | לפני → אחרי |
|---|---|---|
| שני הצדדים שווים לפי ההגדרה. | `rfl` | `⊢ n + 0 = n` ⟶ סגור |
| לפי השוויון [y = x + 7] נחליף [את y ב־x + 7] בתוך [המטרה], ונקבל שצריך להוכיח 2 · (x + 7) = 2 · (x + 7) | `rewrite [‹y = x + 7›]` | `y = x + 7 ⊢ 2 · y = 2 · (x + 7)` ⟶ `y = x + 7 ⊢ 2 · (x + 7) = 2 · (x + 7)` |
| לפי השוויון [a = b] נחליף [את b ב־a] בתוך [P(b)], ונקבל P(a) | `have := ‹P b›`, ואחריו `rewrite [← ‹a = b›] at this` | `a = b, P(b) ⊢ P(a)` ⟶ `a = b, P(b), P(a) ⊢ P(a)` |
| נוכיח באינדוקציה על [n]; בחלק הראשון "בסיס: נוכיח double(0) = 0 + 0", ובשני "צעד: נניח double(n) = n + n ונוכיח double(n + 1) = (n + 1) + (n + 1)" | `induction n with`, ובחלקים `\| zero =>` ו־`\| succ n _ =>` | `⊢ P(n)` ⟶ שני חלקים: `⊢ P(0)`, ו־`P(n) ⊢ P(n + 1)` |
| נשתמש בהגדרת [double] כדי לשכתב את [double(n + 1)] בתוך [המטרה], ונקבל שצריך להוכיח double(n) + 2 = n + 1 + (n + 1). אפשר לפתוח הגדרה גם בטענה שבידינו, ואז התוצאה מצטרפת להנחות. | `rewrite [double]` | `⊢ double(n + 1) = (n + 1) + (n + 1)` ⟶ `⊢ double(n) + 2 = n + 1 + (n + 1)` |
| נכונות המטרה נובעת מחשבון פשוט. | `easylean_goal_only; omega` | `double(n) = n + n ⊢ n + n + 2 = n + 1 + (n + 1)` ⟶ סגור, מהמטרה לבדה |
| נכונות המטרה נובעת מחשבון פשוט / ומ־[n + 1 ≤ n] [ ▾]. בצעד של אינדוקציה, כשכל ההנחות שנבחרו הן הנחות האינדוקציה: ומהנחת האינדוקציה [n + 1 ≤ 2 ^ n] [ ▾] | `have easylean_fact1 := ‹n + 1 ≤ 2 ^ n›; revert easylean_fact1; easylean_goal_only; intros; omega` | `n + 1 ≤ 2^n ⊢ n + 1 + 1 ≤ 2^n · 2` ⟶ סגור, בעזרת n + 1 ≤ 2^n, ורק בה |
| נכונות המטרה נובעת מאלגברה. | `easylean_goal_only; grind` | `oddSum(n) = n · n ⊢ n · n + (2 · n + 1) = (n + 1) · (n + 1)` ⟶ סגור, מהמטרה לבדה |
| נכונות המטרה נובעת מאלגברה / ומהנחת האינדוקציה [2 · sumTo(n) = n · (n + 1)] [ ▾] | `have easylean_fact1 := ‹2 * sumTo n = n * (n + 1)›; revert easylean_fact1; easylean_goal_only; intros; grind` | `2 · sumTo(n) = n · (n + 1) ⊢ 2 · (sumTo(n) + (n + 1)) = (n + 1) · (n + 1 + 1)` ⟶ סגור, בעזרת 2 · sumTo(n) = n · (n + 1), ורק בה |

מלבדם משתמשים במהלכים של יחידות קודמות: "יש לנו ביד בדיוק את מה שאנחנו רוצים להוכיח." (יחידה 0) בשלבים 8.3 ו־8.4, הנחת התנאי (יחידה 1) בשלב 8.7, וחלוקה למקרים, הוכחת "או", שימוש ב"קיים" והוכחת "קיים" (יחידות 2 ו־4) בשלב 8.10.

ההגדרות שהיחידה משתמשת בהן, והשלב שבו כל אחת מופיעה לראשונה:

| הגדרה (בתפריט של פתיחת ההגדרה) | משוואות | מה Lean פותח | שלב |
|---|---|---|---|
| החיבור | `n + 0 = n`, ו־`n + (m + 1) = (n + m) + 1` | `easylean_add_succ` | 8.1 |
| double | `double(0) = 0`, ו־`double(n + 1) = double(n) + 2` | המשוואות של `double` | 8.5 |
| החזקה | `2^0 = 1`, ו־`2^(n + 1) = 2^n · 2` | `Nat.pow_succ` | 8.8 |
| sumTo | `sumTo(0) = 0`, ו־`sumTo(n + 1) = sumTo(n) + (n + 1)` | המשוואות של `sumTo` | 8.9 |
| oddSum | `oddSum(0) = 0`, ו־`oddSum(n + 1) = oddSum(n) + (2n + 1)` | המשוואות של `oddSum` | 8.11 |

**פונקציות משלנו, בהגדרה רקורסיבית.** `double`, `sumTo` ו־`oddSum` מוגדרות ב־`NAT_PRELUDE` (`frontend/src/generator/lean.js`), שנטען רק בשלבים של היחידה (`usesNat`), עם משוואה עבור 0 ומשוואה עבור n + 1, וכך פתיחת ההגדרה היא צעד גלוי. החיבור של Lean מוגדר לפי המחובר השני, ולכן `n + 0 = n` נכון לפי ההגדרה, אבל `0 + n = n` דורש אינדוקציה, כמו ב־Natural Number Game. הלמה `easylean_add_succ` היא המשוואה השנייה של החיבור, בניסוח שהסטודנט מכיר.

**החלפה לפי שוויון.** בוחרים את השוויון מבין השוויונות שבידינו, ואחר כך את ההחלפה: הרשימה מציגה את שני הכיוונים כהחלפות עצמן ("את y ב־x + 7", "את x + 7 ב־y"), כך שאין צורך לחשוב על "שמאל" ו"ימין". המקום הוא המטרה (הראשונה ברשימה) או טענה שבידינו. בטענה שבידינו ההחלפה נעשית בעותק שלה, והתוצאה מצטרפת למה שבידינו, כמו בהסקה קדימה; הטענה המקורית נשארת. ההחלפה לא סוגרת את המטרה בעצמה (`rewrite` ולא `rw`), כך שהסטודנט רואה מה התקבל וסוגר בעצמו.

**אינדוקציה.** המהלך מפצל את ההוכחה לשני חלקים, כמו המהלכים של יחידה 2, ובראש כל חלק כתוב מה מוכיחים בו, לפי המטרה ולפי המשתנה שנבחר: "בסיס: נוכיח P(0)" ו"צעד: נניח P(n) ונוכיח P(n + 1)". כך אי אפשר לשכוח את הבסיס, והנחת האינדוקציה כתובה במפורש. בצעד המשתנה שומר על שמו (`| succ n _ =>`), כמו ב־Logic and Proof, ולהנחת האינדוקציה אין שם: משתמשים בה לפי מה שהיא אומרת, כמו בכל הנחה.

**פתיחת הגדרה.** בוחרים במהלך את ההגדרה מתפריט קבוע של חמש ההגדרות, ואת המקום: המטרה, או טענה שבידינו. כמו בהחלפה, בטענה שבידינו הפתיחה נעשית בעותק שלה, והתוצאה מצטרפת להנחות ("ונקבל …"). אם אין במקום שנבחר מקום לפתוח בו את ההגדרה, ההסבר אומר זאת ("היא נפתחת רק על 0 או על משהו מהצורה n + 1").

**מה התקבל.** פתיחת הגדרה והחלפה לפי שוויון כותבות בשורה נוספת מה התקבל: "ונקבל שצריך להוכיח X" כשהמהלך במטרה, ו"ונקבל Y" כשהוא בטענה שבידינו (ראו [מהלכי ההוכחה](design/moves.md#עקרונות)). לכן בפתרונות שלהלן התוצאה של כל מהלך כזה כתובה כחלק ממנו.

**חשבון ואלגברה בלי להסתיר את הלוגיקה.** החשבון (`omega`) והאלגברה (`grind`), שניהם ב־Lean הבסיסי, בלי Mathlib, משלימים את מה שאינו עיקר השלב. הם לא פותחים את ההגדרות של double, sumTo ו־oddSum, ולכן פתיחת ההגדרה נשארת אצל הסטודנט, וההסבר בכישלון אומר לו את זה ("החשבון מהמטרה לבדה לא מספיק כדי להוכיח אותה. אולי צריך קודם לפתוח הגדרה, או להחליף לפי הנחת האינדוקציה?…"). כל אחד מהם בא בשני מהלכים, כדי שהשימוש במה שבידינו לא יוסתר מאחורי "חשבון פשוט":
- "נכונות המטרה נובעת מחשבון פשוט." ו"נכונות המטרה נובעת מאלגברה." מוכיחים את המטרה לבדה. לפני `omega` או `grind` הם מוציאים את כל מה שבידינו (`easylean_goal_only`, מאקרו ב־`LEAN_PRELUDE` שב־`frontend/src/generator/lean.js`: להנחות אין שמות, ולכן הוא נותן שם לכל אחת בתורה, ב־`rename_i`, ומוחק אותה). כדי להשתמש בהנחת האינדוקציה, מחליפים לפיה קודם, במפורש. ההסבר בכישלון ממשיך: אם אי אפשר להחליף לפי ההנחה (למשל כשהיא אי־שוויון), משתמשים בבלוק "נכונות המטרה נובעת מחשבון פשוט ומ־ ?" (או "מאלגברה ומ־ ?"), ובוחרים בו את ההנחה.
- "נכונות המטרה נובעת מחשבון פשוט / ומ־[A] [ו־B] … [ ▾]" ו"נכונות המטרה נובעת מאלגברה / ומ־…" משתמשים בהנחות שבוחרים בהם, ורק בהן, והבלוק כותב אותן. בארגז הבלוק נקרא "נכונות המטרה נובעת מחשבון פשוט ומ־ ?". את ההנחה הראשונה בוחרים בשדה שאחרי "ומ־". אחריה בא שדה ריק, עם חץ בלבד, שהרשימה שלו מציעה עוד הנחה מאלה שבידינו; בחירה בו כותבת בו "ו־B" ומוסיפה אחריו שדה ריק חדש, כך שאפשר לבחור כמה הנחות שצריך. כשכל ההנחות שנבחרו הן הנחות האינדוקציה של הצעד שהבלוק נמצא בו, "ומ־" נכתב "ומהנחת האינדוקציה" (כשנבחרה אחת) או "ומהנחות האינדוקציה" (כשנבחרו כמה), למשל "נכונות המטרה נובעת מחשבון פשוט ומהנחת האינדוקציה n + 1 ≤ 2 ^ n" (8.8); מחוץ לאינדוקציה, או כשנבחרה הנחה אחרת, נכתב "ומ־", למשל "נכונות המטרה נובעת מחשבון פשוט ומ־n + 1 ≤ n" (8.7). ב־Lean ההנחות שנבחרו מועתקות (`have easylean_fact1 := ‹A›; have easylean_fact2 := ‹B›`), עוברות אל המטרה (`revert`), כל מה שבידינו יוצא (`easylean_goal_only`), וההנחות שנבחרו חוזרות (`intros`); כך `omega` או `grind` משתמשים רק בהן. אם הם לא מצליחים, ההסבר הוא "החשבון לא מספיק כדי להוכיח את המטרה, גם בעזרת ההנחות שבחרתם. אולי צריך לבחור הנחה אחרת, או עוד הנחה, או קודם לפתוח הגדרה?" (ובאלגברה, "האלגברה לא מספיקה…"). המהלכים האלה בארגז רק בשלבים שבהם אי אפשר להחליף לפי ההנחה: כשהיא אי־שוויון (8.7, 8.8), או כשהיא מופיעה במטרה בצורה אחרת (8.9), או כשהחשבון משתמש במה שידוע על העד (8.10).
- הוחלט (לבקשת מחבר הקורס) שהמהלך כותב באילו הנחות הוא משתמש, במקום "ומההנחות שבידינו", שבו `omega` ו־`grind` השתמשו בכל מה שבידינו. שתי סיבות: כך השימוש בהנחה, ובמיוחד בהנחת האינדוקציה, כתוב בהוכחה במפורש, כמו בהוכחה כתובה; ומטרה יכולה לנבוע מחשבון יחד עם כמה הנחות (למשל שתי הנחות האינדוקציה ב־9.5), ולכן אפשר לבחור כמה.

בשלבים שבהם השוויון או האינדוקציה עצמם הם העיקר (8.1–8.4, 8.6) אין חשבון בארגז.

**תצוגה.** פונקציות מוצגות בסימון הקורס (`double(n)`, ולא `double n`), וכפל כ־`·`. מספרים מוצגים בחלונית מצב ההוכחה בשורה נפרדת, "מספרים: n", כמו עצמים וקבוצות.

## שלבים

לכל שלב: מה לומדים בו, למה הוא בנוי כך, איך אנחנו רוצים שסטודנטים יפתרו אותו, ושיקולים ושאלות שעוד צריך להכריע. צילומי הפתרונות נוצרים מ־`frontend/e2e/solutions.js` (ראו [יחידה 0](00-getting-started.md#שלבים)).

**סדר היחידה.** קודם שוויון (8.1–8.4), כי האינדוקציה משתמשת בהחלפה, ואחר כך אינדוקציה (8.5–8.10) ובונוס (8.11).

### שלב 8.1: שוויון לפי ההגדרה

`⊢ n + 0 = n` · מספרים: n · בארגז: שוויון לפי ההגדרה

**מה לומדים.** רפלקסיביות: שוויון ששני צדדיו זהים לפי ההגדרות מוכח מיד. ומספרים טבעיים, עם הגדרת החיבור.

**למה כך.** כמו הרמה הראשונה של Natural Number Game. הטענה נבחרה כך שהיא נכונה לפי ההגדרה, כדי שבשלב 8.6 יהיה ניגוד ל־`0 + n = n`, שאינה.

**פתרון.** "שני הצדדים שווים לפי ההגדרה.": n + 0 הוא n לפי הגדרת החיבור.

![שלב 8.1](images/unit8-level1-a.png)

**שיקולים ושאלות להכרעה.**
- "לפי ההגדרה" כולל גם חישוב: המהלך סוגר גם `2 + 2 = 4` וגם `double(0) = 0 + 0` בלי לפתוח הגדרה. הגבול בין "לפי ההגדרה" ל"צריך הוכחה" לא תמיד ברור לסטודנט. האם להסביר בטקסט שההגדרות "מחושבות" עד הסוף?
- בשלב יש מהלך אחד ואין מה לבחור. הוא מציג בעיקר את המספרים ואת הגדרת החיבור; אפשר לצרף אותו לטקסט של שלב 8.2.

### שלב 8.2: מחליפים לפי שוויון

`y = x + 7 ⊢ 2 · y = 2 · (x + 7)` · מספרים: x, y · בארגז: החלפה לפי שוויון, שוויון לפי ההגדרה

**מה לומדים.** העיקרון של החלפת שווה בשווה (=E, חוק לייבניץ), ואיך בוחרים במהלך שוויון, החלפה ומקום.

**למה כך.** אותה דוגמה כמו ב־Natural Number Game ("substitute in for y"). ההחלפה לא סוגרת את המטרה, כך שהסטודנט רואה ששני הצדדים נעשו זהים, וסוגר בעיקרון של שלב 8.1. שני העקרונות של השוויון מופיעים כך זה אחר זה.

**פתרון.** "לפי השוויון y = x + 7 נחליף את y ב־x + 7 בתוך המטרה, ונקבל שצריך להוכיח 2 · (x + 7) = 2 · (x + 7)", ו"שני הצדדים שווים לפי ההגדרה."

![שלב 8.2](images/unit8-level2-a.png)

**שיקולים ושאלות להכרעה.**
- בבלוק שלושה שדות, וזה המהלך הראשון בקורס שבוחרים בו גם כיוון וגם מקום. ברשימת ההחלפות יש גם "את x + 7 ב־y", והבחירה בה נותנת `2 · y = 2 · y`, שגם היא נסגרת לפי ההגדרה. האם זה מבלבל, או דווקא מראה שיש יותר מדרך אחת?
- שני העקרונות מוצגים בשני שלבים קצרים. אפשר לשקול שלב שבו ההחלפה צריכה לקרות פעמיים, לפני שעוברים לכיוון.

### שלב 8.3: כיוון ההחלפה

`a = b, P(b) ⊢ P(a)` · עצמים: a, b · בארגז: החלפה לפי שוויון, יש לנו ביד

**מה לומדים.** שלשוויון יש שני כיוונים, ושאפשר להחליף גם בטענה שבידינו, לא רק במטרה.

**למה כך.** החלפה בכיוון הלא נכון היא טעות נפוצה, ו־Natural Number Game מקדיש לה שלב. כאן הכיוון מוצג כהחלפה עצמה, ולכן השאלה היא לא "שמאל או ימין" אלא מה מחליפים במה, ואיפה. התחום מופשט (כמו ביחידה 4), כדי להראות שהשוויון אינו רק של מספרים. יש שתי דרכים, והן נבדלות במקום: בטענה שבידינו או במטרה.

**פתרון א: בטענה שבידינו.** "לפי השוויון a = b נחליף את b ב־a בתוך P(b), ונקבל P(a)". P(a) מצטרפת למה שבידינו, ו"יש לנו ביד בדיוק את מה שאנחנו רוצים להוכיח."

![שלב 8.3, בטענה שבידינו](images/unit8-level3-a.png)

**פתרון ב: במטרה.** "לפי השוויון a = b נחליף את a ב־b בתוך המטרה, ונקבל שצריך להוכיח P(b)", וזה בידינו.

![שלב 8.3, במטרה](images/unit8-level3-b.png)

**שיקולים ושאלות להכרעה.**
- כיוון שגוי מוסבר ("ב־P(b) לא מופיע a, ולכן אין מה להחליף. אולי צריך להחליף בכיוון השני, או במקום אחר?"), אבל השלב לא מתחיל בטעות מתוכננת: כשההחלפה כתובה במפורש, טעות כזאת נראית כבר לפני הבדיקה. האם עדיין כדאי שהסטודנט ייתקל בה?
- בהחלפה בטענה שבידינו, P(b) נשארת ו־P(a) מתווספת, והבלוק כותב "ונקבל P(a)", כמו בספרים. האם צריך להסביר שהטענה הישנה נשארת בידינו?

### שלב 8.4: שרשרת של שוויונות

`a = b, b = c ⊢ a = c` · עצמים: a, b, c · בארגז: החלפה לפי שוויון, יש לנו ביד

**מה לומדים.** טרנזיטיביות, כתוצאה של העיקרון של החלפה.

**למה כך.** forall x מראה שהסימטריה והטרנזיטיביות נובעות משני העקרונות של 8.1 ו־8.2 בלבד; כאן רואים זאת בפועל. יש שתי דרכים, לפי השוויון שבוחרים, וטקסט הסיום מזכיר גם את הסימטריה.

**פתרון א: את a ב־b.** "לפי השוויון a = b נחליף את a ב־b בתוך המטרה, ונקבל שצריך להוכיח b = c", וזה בידינו.

![שלב 8.4, את a ב־b](images/unit8-level4-a.png)

**פתרון ב: את c ב־b.** "לפי השוויון b = c נחליף את c ב־b בתוך המטרה, ונקבל שצריך להוכיח a = b", וזה בידינו.

![שלב 8.4, את c ב־b](images/unit8-level4-b.png)

**שיקולים ושאלות להכרעה.**
- שרשרת מתקבלת כאן מהחלפות רצופות. האם צריך מהלך נפרד לשרשרת "a = b = c", כמו ב־Waterproof וב־Verbose Lean?
- הסימטריה (מ־a = b נובע b = a) מוזכרת רק בטקסט הסיום. היא שלב קצר וטוב לכיוון ההחלפה, ואפשר להוסיף אותה לפני השלב הזה.

### שלב 8.5: אינדוקציה ראשונה

`⊢ double(n) = n + n` · מספרים: n · בארגז: אינדוקציה, פתיחת הגדרה, החלפה לפי שוויון, שוויון לפי ההגדרה, חשבון

**מה לומדים.** אינדוקציה: בסיס, צעד והנחת האינדוקציה. ופתיחה של הגדרה רקורסיבית.

**למה כך.** פונקציה פשוטה שמוגדרת ברקורסיה, כך שהמבנה של ההוכחה בולט: פתיחת ההגדרה, החלפה לפי הנחת האינדוקציה, חשבון. הטקסט מסביר את האינדוקציה כשרשרת "מ־0 ל־1, מ־1 ל־2". הכותרות של החלקים כותבות את הבסיס ואת הצעד לפי המטרה, כך שהסטודנט רואה מה בדיוק הנחת האינדוקציה ומה צריך להוכיח בצעד. החשבון כאן הוא מהמטרה לבדה, ולכן ההחלפה לפי הנחת האינדוקציה היא חלק הכרחי מההוכחה, והשימוש בהנחה גלוי.

**פתרון.** "נוכיח באינדוקציה על n." בחלק "בסיס: נוכיח double(0) = 0 + 0": "נשתמש בהגדרת double כדי לשכתב את double(0) בתוך המטרה, ונקבל שצריך להוכיח 0 = 0 + 0", ו"שני הצדדים שווים לפי ההגדרה." בחלק "צעד: נניח double(n) = n + n ונוכיח double(n + 1) = (n + 1) + (n + 1)": "נשתמש בהגדרת double כדי לשכתב את double(n + 1) בתוך המטרה, ונקבל שצריך להוכיח double(n) + 2 = n + 1 + (n + 1)"; "לפי הנחת האינדוקציה double(n) = n + n נחליף את double(n) ב־n + n בתוך המטרה, ונקבל שצריך להוכיח n + n + 2 = n + 1 + (n + 1)"; ו"נכונות המטרה נובעת מחשבון פשוט."

![שלב 8.5](images/unit8-level5-a.png)

**שיקולים ושאלות להכרעה.**
- השלב מציג שלושה מהלכים חדשים יחד (אינדוקציה, פתיחת הגדרה, חשבון), בניגוד לכלל שבשלב שמציג מהלך חדש יש רק אותו. אפשר להקדים את שלב 8.6, שאין בו חשבון, או שלב שבו הצעד הוא רק פתיחת הגדרה והחלפה.
- הוחלט: ההחלפה הכרחית. חשבון שמשתמש גם במה שבידינו היה סוגר את הצעד מיד אחרי פתיחת ההגדרה, בלי ההחלפה. לכן "נכונות המטרה נובעת מחשבון פשוט" מוכיח את המטרה לבדה, ובלי ההחלפה double(n) הוא בשבילו מספר לא ידוע, וההסבר מציע להחליף לפי הנחת האינדוקציה. הסיבה: להשתמש בהנחה במפורש, ולא להחביא את השימוש בה מאחורי "חשבון פשוט". על פתיחת ההגדרה אי אפשר לדלג, וטקסט הסיום אומר את זה.
- גם בבסיס אפשר לדלג על פתיחת ההגדרה: double(0) = 0 + 0 נכון לפי ההגדרה, ו"שני הצדדים שווים לפי ההגדרה" סוגר אותו מיד (ראו 8.1).

### שלב 8.6: 0 + n = n

`⊢ 0 + n = n` · מספרים: n · בארגז: אינדוקציה, פתיחת הגדרה, החלפה לפי שוויון, שוויון לפי ההגדרה

**מה לומדים.** שטענה שנראית מובנת מאליה יכולה לדרוש אינדוקציה, ולהבחין בין "לפי ההגדרה" ל"לפי הוכחה".

**למה כך.** הניגוד לשלב 8.1, כמו ב־Natural Number Game ("Wait, don't we already know that? No!"). אין חשבון בארגז: כל צעד הוא פתיחת הגדרה, החלפה או שוויון לפי ההגדרה, כך שהאינדוקציה עצמה במרכז. אם הסטודנט מנסה "שני הצדדים שווים לפי ההגדרה" ישירות, ההסבר אומר ששני הצדדים לא שווים לפי ההגדרות בלבד, ומציע אינדוקציה.

**פתרון.** "נוכיח באינדוקציה על n." בבסיס, 0 + 0 = 0, ו"שני הצדדים שווים לפי ההגדרה." בצעד ("נניח 0 + n = n ונוכיח 0 + (n + 1) = n + 1"): "נשתמש בהגדרת החיבור כדי לשכתב את 0 + (n + 1) בתוך המטרה, ונקבל שצריך להוכיח 0 + n + 1 = n + 1"; "לפי הנחת האינדוקציה 0 + n = n נחליף את 0 + n ב־n בתוך המטרה, ונקבל שצריך להוכיח n + 1 = n + 1"; ו"שני הצדדים שווים לפי ההגדרה."

![שלב 8.6](images/unit8-level6-a.png)

**שיקולים ושאלות להכרעה.**
- הנחת האינדוקציה היא כאן שוויון, ולכן משתמשים בה במהלך ההחלפה. זו ההזדמנות הראשונה לראות שהנחת האינדוקציה היא הנחה רגילה. כדאי לומר זאת בטקסט הסיום?
- Natural Number Game ממשיך מכאן לחילוף ולקיבוץ של החיבור. בלי מנגנון לשימוש בטענות שכבר הוכחו, אין המשך טבעי כזה.

### שלב 8.7: צעד בלי בסיס

`⊢ (n + 1 ≤ n) → (n + 1 + 1 ≤ n + 1)` · מספרים: n · בארגז: הנחת התנאי, חשבון בעזרת ההנחות

**מה לומדים.** למה הבסיס נחוץ: לטענה שקרית (n + 1 ≤ n) יש צעד נכון. ומהלך חדש, "נכונות המטרה נובעת מחשבון פשוט ומ־ ?": הנחה שהיא אי־שוויון אי אפשר להחליף לפיה, ולכן החשבון משתמש בה: בוחרים אותה בבלוק, והוא כותב אותה.

**למה כך.** התרגיל "Propriété héréditaire mais fausse" של D∃∀duction, נגד הטעות הנפוצה שהבסיס הוא פורמליות. הסטודנט מוכיח את הצעד בעצמו, וטקסט הסיום מראה שהבסיס, 0 + 1 ≤ 0, לא נכון, ולכן השרשרת לא מתחילה. אין אינדוקציה בארגז: מוכיחים רק את הצעד. התנאי, n + 1 ≤ n, הוא אי־שוויון, ובלעדיו המטרה לא נכונה, ולכן זה המקום הטבעי להציג את החשבון בעזרת ההנחות; הרמז אומר שאי אפשר להחליף לפיו. בארגז אין החשבון מהמטרה לבדה, כמו בכל שלב שמציג מהלך חדש.

**פתרון.** "כדי להוכיח את הגרירה, נניח n + 1 ≤ n ונוכיח n + 1 + 1 ≤ n + 1." ו"נכונות המטרה נובעת מחשבון פשוט ומ־n + 1 ≤ n". הצעד הזה לא בתוך אינדוקציה, ולכן הבלוק כותב "ומ־" ולא "ומהנחת האינדוקציה".

![שלב 8.7](images/unit8-level7-a.png)

**שיקולים ושאלות להכרעה.**
- השלב מתבסס על הסבר בטקסט יותר מאשר על ההוכחה, שהיא קצרה. חלופה: לבקש מהסטודנט להוכיח גם שהבסיס לא נכון, ¬(0 + 1 ≤ 0), במהלכים של יחידה 3 ובחשבון. כך שני חלקי הטיעון נעשים בהוכחה.
- חלופה אחרת: לתת לסטודנט לנסות להוכיח את n + 1 ≤ n באינדוקציה, ולהיתקע בבסיס. זה דורש שלב בלי פתרון, ואין לנו מנגנון כזה.

### שלב 8.8: אינדוקציה ואי־שוויון

`⊢ n + 1 ≤ 2^n` · מספרים: n · בארגז: אינדוקציה, פתיחת הגדרה, חשבון, חשבון בעזרת ההנחות

**מה לומדים.** שאינדוקציה מוכיחה גם אי־שוויונות, ושמשתמשים בהנחת האינדוקציה גם בלי להחליף לפיה, במהלך שאומר זאת.

**למה כך.** הדוגמה הראשונה ב־Mechanics of Proof. אחרי פתיחת הגדרת החזקה החשבון לינארי (2^n הוא "איבר" אחד), ולכן מספיק החשבון. בניגוד לשלבים 8.5–8.6, הנחת האינדוקציה היא אי־שוויון, ואין מה להחליף לפיה: בצעד משתמשים בה בחשבון בעזרת ההנחות, כמו בשלב 8.7, וטקסט הפתיחה אומר זאת. בבסיס אין הנחות, ומספיק החשבון מהמטרה לבדה, ולכן שני מהלכי החשבון בארגז.

**פתרון.** "נוכיח באינדוקציה על n." בבסיס ("נוכיח 0 + 1 ≤ 2^0"): "נכונות המטרה נובעת מחשבון פשוט." בצעד ("נניח n + 1 ≤ 2^n ונוכיח (n + 1) + 1 ≤ 2^(n + 1)"): "נשתמש בהגדרת החזקה כדי לשכתב את 2 ^ (n + 1) בתוך המטרה, ונקבל שצריך להוכיח n + 1 + 1 ≤ 2 ^ n · 2"; ו"נכונות המטרה נובעת מחשבון פשוט ומהנחת האינדוקציה n + 1 ≤ 2 ^ n".

![שלב 8.8](images/unit8-level8-a.png)

**שיקולים ושאלות להכרעה.**
- החשבון של Lean מכיר את החזקה: הוא סוגר את הבסיס בלי לפתוח את ההגדרה, וגם את הצעד בלי לפתוח אותה, בחשבון בעזרת ההנחות (נבדק ב־Lean). לכן פתיחת ההגדרה כאן לא נחוצה, אף שהפתיחה והרמז מציעים אותה (טקסט הסיום כבר לא טוען שהיא נחוצה). אם רוצים שתהיה נחוצה, אפשר להגדיר חזקה משלנו, כמו double, כדי שהחשבון לא יכיר אותה.
- הוחלט: זה השלב הראשון שבו הנחת האינדוקציה לא מופיעה במטרה אחרי הפתיחה, והשימוש בה כתוב במפורש: בוחרים אותה בבלוק, שנקרא "נכונות המטרה נובעת מחשבון פשוט ומהנחת האינדוקציה n + 1 ≤ 2 ^ n", וטקסט הפתיחה מסביר שאי אפשר להחליף לפי אי־שוויון.
- שני מהלכי החשבון בארגז. בבסיס אין הנחות, ולכן אין מה לבחור בחשבון בעזרת ההנחות (השדה שלו נשאר "?", והמהלך לא נבדק עד שממלאים אותו); את הבסיס סוגרים בחשבון מהמטרה לבדה.

### שלב 8.9: סכום המספרים

`⊢ 2 · sumTo(n) = n · (n + 1)` · מספרים: n · בארגז: אינדוקציה, פתיחת הגדרה, שוויון לפי ההגדרה, אלגברה בעזרת ההנחות

**מה לומדים.** את נוסחת הסכום הקלאסית, ואת מהלך האלגברה בעזרת ההנחות שבוחרים: "נכונות המטרה נובעת מאלגברה ומ־ ?".

**למה כך.** הנוסחה דורשת כפל של משתנים, ולכן היא מחוץ לטווח של החשבון; `grind` עושה את האלגברה. הנוסחה מנוסחת כ"פעמיים הסכום", כדי להימנע מחילוק במספרים טבעיים (אזהרה של HTPI). אחרי פתיחת ההגדרה המטרה מדברת על 2 · (sumTo(n) + (n + 1)), ולא על 2 · sumTo(n) כמו הנחת האינדוקציה, ולכן אי אפשר להחליף לפיה: האלגברה משתמשת בה: בוחרים אותה בבלוק, והוא כותב אותה. טקסט הפתיחה מסביר את זה. אין החלפה בארגז.

**פתרון.** "נוכיח באינדוקציה על n." בבסיס ("נוכיח 2 · sumTo(0) = 0 · (0 + 1)"): "נשתמש בהגדרת sumTo כדי לשכתב את sumTo(0) בתוך המטרה, ונקבל שצריך להוכיח 2 · 0 = 0 · (0 + 1)", ו"שני הצדדים שווים לפי ההגדרה." בצעד ("נניח 2 · sumTo(n) = n · (n + 1) ונוכיח 2 · sumTo(n + 1) = (n + 1) · (n + 1 + 1)"): "נשתמש בהגדרת sumTo כדי לשכתב את sumTo(n + 1) בתוך המטרה, ונקבל שצריך להוכיח 2 · (sumTo(n) + (n + 1)) = (n + 1) · (n + 1 + 1)"; ו"נכונות המטרה נובעת מאלגברה ומהנחת האינדוקציה 2 · sumTo(n) = n · (n + 1)".

![שלב 8.9](images/unit8-level9-a.png)

**שיקולים ושאלות להכרעה.**
- הוחלט: השימוש בהנחת האינדוקציה כתוב במפורש, בבלוק "נכונות המטרה נובעת מאלגברה ומהנחת האינדוקציה 2 · sumTo(n) = n · (n + 1)", ולא סמוי מאחורי "אלגברה". חלופה שבה ההחלפה אפשרית: מהלך של פתיחת סוגריים (2 · (sumTo(n) + (n + 1)) = 2 · sumTo(n) + 2 · (n + 1)), ואחריו החלפה לפי הנחת האינדוקציה ואלגברה מהמטרה לבדה. זה מוסיף מהלך חדש בשביל צעד אחד.
- האלגברה בעזרת ההנחות מוצגת כאן, לפני האלגברה מהמטרה לבדה (שמוצגת רק בשלב 8.11); בחשבון הסדר הפוך (8.5 ואחר כך 8.7). הכרטיס שלה מתאר אותה בלי הפניה לאלגברה מהמטרה לבדה ("בעזרת ההנחות שבוחרים בבלוק (אחת או יותר)"), ולכן הסדר לא מפריע להבנתו. אם רוצים אחידות עם החשבון, אפשר להחליף את הסדר של 8.9 ו־8.11.
- גם כאן אפשר לסגור את הבסיס בלי לפתוח את ההגדרה.

### שלב 8.10: תרגיל מסכם: זוגי או אי־זוגי

`⊢ (∃j (n = 2 · j)) ∨ (∃j (n = 2 · j + 1))` · מספרים: n · בארגז: אינדוקציה, חלוקה למקרים, הוכחת "או", שימוש ב"קיים", הוכחת "קיים", שוויון לפי ההגדרה, חשבון בעזרת ההנחות

**מה לומדים.** אינדוקציה יחד עם הכלים של יחידות 2 ו־4: הנחת האינדוקציה היא "או", ובכל מקרה מקבלים עצם מ"קיים" ובוחרים עד. ועד שהוא ביטוי, ולא שם של עצם שבידינו.

**למה כך.** התרגיל מופיע ב־D∃∀duction וב־Mechanics of Proof. הוא מראה שהנחת האינדוקציה היא הנחה רגילה, שמשתמשים בה בכל הכלים. העדים 0 ו־j₀ + 1 לא מופיעים ברשימת העצמים, ולכן כותבים אותם ב"✎ כתיבה ידנית"; הטקסט אומר זאת מראש. בסוף כל מקרה החשבון משתמש במה שידוע על j₀ (n = 2 · j₀, או n = 2 · j₀ + 1), ולכן הוא החשבון בעזרת ההנחות, ובוחרים בו את ההנחה הזאת; הרמז אומר זאת. אין החלפה בארגז (ראו בשיקולים).

**פתרון.** "נוכיח באינדוקציה על n." בבסיס ("נוכיח (∃j (0 = 2 · j)) ∨ (∃j (0 = 2 · j + 1))"): די להוכיח ∃j (0 = 2 · j); נבחר את העצם 0 (בכתיבה ידנית) ונוכיח 0 = 2 · 0, ו"שני הצדדים שווים לפי ההגדרה." בצעד, נחלק למקרים לפי ה"או" שבהנחת האינדוקציה. במקרה הראשון, לפי ה"קיים" ∃j (n = 2 · j) יהי j₀ עצם כך ש־n = 2 · j₀; די להוכיח ∃j (n + 1 = 2 · j + 1); נבחר את העצם j₀ ונוכיח n + 1 = 2 · j₀ + 1, ו"נכונות המטרה נובעת מחשבון פשוט ומ־n = 2 · j₀". במקרה השני, יהי j₀ עצם כך ש־n = 2 · j₀ + 1; די להוכיח ∃j (n + 1 = 2 · j); נבחר את העצם j₀ + 1 (בכתיבה ידנית) ונוכיח n + 1 = 2 · (j₀ + 1), ו"נכונות המטרה נובעת מחשבון פשוט ומ־n = 2 · j₀ + 1". ההנחות האלה אינן הנחות האינדוקציה, ולכן הבלוק כותב "ומ־".

![שלב 8.10](images/unit8-level10-a.png)

**שיקולים ושאלות להכרעה.**
- כדי לכתוב את העד j₀ + 1 צריך להקליד את האינדקס ₀, שאין במקלדת. אפשר לקבל גם `j0`, או להציע ברשימה גם את j₀ + 1 (לפי העצמים שבידינו), או להוסיף מקלדת סימנים.
- המהלך כותב "נבחר את העצם 0": מספר נקרא כאן "עצם". זה עקבי עם יחידה 4, אבל אולי מוזר לסטודנטים.
- כאן ההנחה n = 2 · j₀ היא שוויון, ואפשר היה להחליף לפיה (את n ב־2 · j₀) ולסגור בחשבון מהמטרה לבדה, כמו ב־8.5. החשבון בעזרת ההנחות חוסך מהלך בכל מקרה, בהוכחה שהיא ממילא הארוכה ביחידה, והעיקר בשלב הוא השילוב של האינדוקציה עם "או" ו"קיים"; והבלוק עדיין כותב באיזו הנחה הוא משתמש ("ומ־n = 2 · j₀"). אם רוצים שגם כאן השימוש יהיה בהחלפה, מוסיפים אותה לארגז ומחליפים את החשבון.
- זו ההוכחה הארוכה ביותר ביחידה, עם שלוש רמות של חלקים מקוננים. כדאי לבדוק עם סטודנטים אם הרמזים מספיקים, או לפצל לשני שלבים (למשל, קודם רק הצעד, כשהנחת האינדוקציה היא הנחה רגילה).

### שלב 8.11: שלב בונוס: סכום האי־זוגיים

`⊢ oddSum(n) = n · n` · מספרים: n · בארגז: אינדוקציה, פתיחת הגדרה, החלפה לפי שוויון, שוויון לפי ההגדרה, אלגברה

**מה לומדים.** אינדוקציה עם נוסחה נוספת, הפעם בלי עזרה מפורטת. ומהלך האלגברה מהמטרה לבדה, "נכונות המטרה נובעת מאלגברה.", שמשלים את האלגברה בעזרת ההנחות של שלב 8.9.

**למה כך.** סכום האי־זוגיים הוא תרגיל קלאסי שעובר ב־Lean הבסיסי (הבונוס שהוצע במקור, `3 ∣ n³ + 2n`, לא עובר גם עם `grind`). הטקסט מראה את הדוגמאות הראשונות (1, 4, 9), כדי שהסטודנט יראה את הדפוס לפני ההוכחה. בניגוד ל־8.9, כאן oddSum(n) מופיע במטרה אחרי הפתיחה בדיוק כמו בהנחת האינדוקציה, ולכן מחליפים לפיה, ואחר כך מספיקה אלגברה מהמטרה לבדה; טקסט הפתיחה אומר זאת. כך הצעד הוא כמו ב־8.5, עם אלגברה במקום חשבון.

**פתרון.** "נוכיח באינדוקציה על n." בבסיס: "נשתמש בהגדרת oddSum כדי לשכתב את oddSum(0) בתוך המטרה, ונקבל שצריך להוכיח 0 = 0 · 0", ו"שני הצדדים שווים לפי ההגדרה." בצעד ("נניח oddSum(n) = n · n ונוכיח oddSum(n + 1) = (n + 1) · (n + 1)"): "נשתמש בהגדרת oddSum כדי לשכתב את oddSum(n + 1) בתוך המטרה, ונקבל שצריך להוכיח oddSum(n) + (2 · n + 1) = (n + 1) · (n + 1)"; "לפי הנחת האינדוקציה oddSum(n) = n · n נחליף את oddSum(n) ב־n · n בתוך המטרה, ונקבל שצריך להוכיח n · n + (2 · n + 1) = (n + 1) · (n + 1)"; ו"נכונות המטרה נובעת מאלגברה."

![שלב 8.11](images/unit8-level11-a.png)

**שיקולים ושאלות להכרעה.**
- הוחלט: ההחלפה הכרחית, כמו בשלב 8.5. האלגברה מהמטרה לבדה לא משתמשת בהנחת האינדוקציה, ובלי ההחלפה oddSum(n) הוא בשבילה מספר לא ידוע. הסיבה: להשתמש בהנחה במפורש, ולא להחביא את השימוש בה מאחורי "אלגברה".
- הבונוס דומה מאוד ל־8.9. אפשרות לבונוס שונה: אינדוקציה שבה הנחת האינדוקציה היא גרירה או "לכל", למשל טענה עם שני משתנים.

## רקע: מה עושים מדריכים אחרים

- **שוויון כלוגיקה:** forall x (פרק 39) מגדיר שני כללים, =I ("c = c") ו־=E (החלפה, חוק לייבניץ), ומוכיח מהם סימטריה וטרנזיטיביות. Logic and Proof (פרק 17) מציג את האינדוקציה עם אותו שם משתנה בבסיס ובצעד, כמו כאן.
- **Natural Number Game** ([NNG4](https://github.com/leanprover-community/NNG4)): עולם ההדרכה (rfl, rw, כיוון ההחלפה) ועולם החיבור (0 + n = n כאינדוקציה ראשונה, ואחר כך חילוף וקיבוץ). המשחק בונה את המספרים, החיבור והכפל בעצמו, ולכן כל צעד הוא החלפה לפי הגדרה או לפי טענה קודמת, בלי אוטומציה.
- **ניסוח:**
  - Verbose Lean: "We rewrite using …", "Calc a = b by hypothesis"; לאינדוקציה "Let's prove by induction".
  - Waterproof: "We use induction on n. We first show the base case… We now show the induction step."
  - D∃∀duction: "Choose which expression you want to replace"; "Base case / Induction step".
- **סדרות תרגילים:**
  - HTPI 6.1: `3 ∣ n³ + 2n`, סכום חזקות של 2, `2ⁿ > n²` עבור n ≥ 5.
  - Mechanics of Proof 6: `2ⁿ ≥ n + 1`, זוגי או אי־זוגי, שאריות.
  - D∃∀duction: סדרות, ו"תכונה שעוברת מ־n ל־n + 1 אבל לא נכונה".
- **טעויות נפוצות:**
  - שכחת הבסיס, או מחשבה שהוא לא נחוץ. ממנה נולד שלב 8.7.
  - החלפה בכיוון הלא נכון. ממנה נולד שלב 8.3.
  - בלבול בין `n + 0 = n` לבין `0 + n = n`. ממנו נולד שלב 8.6.
  - שימוש בהנחת האינדוקציה לפני שהצד שלה מופיע במטרה (לפני פתיחת ההגדרה).
- **מקורות:**
  - [forall x, פרק 39](https://forallx.openlogicproject.org/html/Ch39.html)
  - [Logic and Proof, פרק 17](https://leanprover-community.github.io/logic_and_proof/the_natural_numbers_and_induction.html)
  - [How To Prove It with Lean, 6.1](https://djvelleman.github.io/HTPIwL/Chap6.html)
  - [The Mechanics of Proof, 6](https://hrmacbeth.github.io/math2001/06_Induction.html)

**ביחידה 9** אותו בלוק אינדוקציה עובד גם על רשימות, עצים ונוסחאות: הוא פותח חלק לכל דרך לבנות את המבנה של השלב. המספרים הטבעיים הם המקרה של שתי דרכים, 0 ו־n + 1, ולכן ביחידה הזאת הבלוק נשאר כמו שהוא.

**הנחת האינדוקציה בשמה.** הוחלט (לבקשת מחבר הקורס) שמהלך שמשתמש בהנחת האינדוקציה יאמר זאת, כמו בהוכחה כתובה: החלפה לפיה נכתבת "לפי הנחת האינדוקציה … נחליף …" (במקום "לפי השוויון"), סיום שהמטרה בו היא ההנחה נכתב "זו בדיוק הנחת האינדוקציה.", וחשבון או אלגברה שכל ההנחות שנבחרו בהם הן הנחות האינדוקציה נכתבים "… ומהנחת האינדוקציה A" או "… ומהנחות האינדוקציה A ו־B" (במקום "ומ־"). הבלוק מזהה את ההנחות לפי הכותרת של החלק "צעד" שהוא נמצא בו; מחוץ לאינדוקציה הניסוח לא משתנה.

## שאלות שנוגעות ליחידה כולה

- **הוחלט: חשבון ואלגברה לא מסתירים את השימוש במה שבידינו.** כשהחשבון והאלגברה השתמשו במה שבידינו, ההחלפה לפי הנחת האינדוקציה לא הייתה נחוצה בשלבים 8.5 ו־8.11, ובשלבים 8.7–8.9 השימוש בהנחות היה סמוי. הבקשה של מחבר הקורס: להשתמש בהנחה במפורש, ולא להחביא את השימוש בה מאחורי "חשבון פשוט". לכן כל אחד מהם בא בשני מהלכים: מהמטרה לבדה ("נכונות המטרה נובעת מחשבון פשוט.", "נכונות המטרה נובעת מאלגברה."), שלפניו מחליפים במפורש לפי ההנחה (8.5, 8.11); ו"… ומ־ ?", שבו בוחרים את ההנחות שהחשבון משתמש בהן, ורק בהן הוא משתמש, כשאי אפשר להחליף לפי ההנחה: היא אי־שוויון (8.7, 8.8), או מופיעה במטרה בצורה אחרת (8.9), או שהחשבון משתמש במה שידוע על העד (8.10). קודם המהלך הזה היה "… ומההנחות שבידינו", והשתמש בכל מה שבידינו; הוחלט (לבקשת מחבר הקורס) שיכתוב את ההנחות שהוא משתמש בהן, כדי שהשימוש בהן, ובמיוחד בהנחת האינדוקציה, יהיה כתוב בהוכחה, וכי מטרה יכולה לנבוע מחשבון יחד עם כמה הנחות. בכך הוכרעה גם השאלה שנשארה פתוחה, שהמהלך לא בודק שאי אפשר היה להחליף: עדיין מותר לבחור בו הנחה שאפשר היה להחליף לפיה (למשל ב־8.10, שבו ההנחה n = 2 · j₀ היא שוויון), אבל זה כבר לא מסתיר דבר, כי ההוכחה כותבת במפורש באיזו הנחה השתמשו.
- **שם המשתנה בצעד.** הצעד כותב "נניח P(n) ונוכיח P(n + 1)", כמו Logic and Proof, אף שה־n שבצעד הוא מספר מסוים ולא ה־n של המטרה. ביחידה 4 הקפדנו להבחין בין משתנה קשור לעצם (x₀). האם לתת בצעד שם חדש (k, או n₀), או שהמוסכמה המקובלת בספרים חשובה יותר?
- **שני מהלכי הגדרה.** ביחידות 6–7 מהלך ההגדרה בוחר טענה מהמטרה או ממה שבידינו, וכותב "פירושו …". כאן פתיחת ההגדרה עובדת גם היא על המטרה או על טענה שבידינו, אבל בוחרים בה הגדרה מתפריט קבוע, גם אם היא לא מופיעה במקום שנבחר, והיא כותבת "ונקבל …". האם לאחד אותם למהלך אחד שנקרא אותו דבר?
- **טענות שכבר הוכחו.** כמו ב־Natural Number Game, אפשר היה להשתמש ב־`0 + n = n` משלב 8.6 בשלבים הבאים. השאלה עלתה גם ביחידות 2, 5 ו־6.
- **אינדוקציה חזקה ואינדוקציה מנקודה מסוימת** (n ≥ 5): לא נכללו. האם להוסיף?
- **הקלדת סימנים.** העדים בשלב 8.10, ובמיוחד האינדקס ₀, מוקלדים בשדה. מקלדת סימנים תעזור גם כאן.
