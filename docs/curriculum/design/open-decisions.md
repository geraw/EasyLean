# החלטות פתוחות

<div dir="rtl">

מסמך זה מרכז את דרישות הבסיס ואת ההחלטות שעלו מהקטלוג ומהארכיטקטורה.

## דרישות בסיס

1. האם הסטודנט בוחר שמות להנחות, או שהמערכת מייצרת אותם?
2. האם שלב השרשרת (`(P → Q) → (Q → R) → P → R`) מתאים כבר ליחידה 1?
3. **ניסוח צעדי הוכחה:** איזה סגנון עברי קבוע ישמש לתיאור מהלכי הוכחה בבלוקים? למשל: „נניח ש־P מתקיים”, „יהי x”, או „נגיע לסתירה”.
4. מה מנגנון השמירה והחזרה לתרגיל?

## חדשות

5. **היקף וסדר:** מתחילים בלוגיקה, כולל לוגיקה קלאסית, ורק בשלב מאוחר יותר עוברים לקבוצות.
6. **מנוע:** לעבוד ישירות עם שרת Lean, ללא מנוע JS פסוקי.
7. **Mathlib:** מותר להסתמך עליה, כולל טקטיקות כמו `use` ו-`contrapose!`.
8. **לוגיקה קלאסית:** מציגים `by_contra` ו-`by_cases` לפני המעבר לקבוצות, במסגרת יחידה 3.
9. **`exact` מול `assumption`:** האם לבחור הנחה בעצמו, או שהמערכת מוצאת?
10. **סדר מטרות:** כשבלוק יוצר כמה מטרות (`constructor`, `rcases`), איך מציגים אותן בבלוקים (תתי-בלוקים, או בלוק אחד שמקבל רצף)?
11. **שפה:** האם נדרשת גם גרסה באנגלית?
