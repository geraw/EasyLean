# יחידה 9 — אינדוקציה מבנית

<div dir="rtl">

**מטרה:** להוכיח טענה על כל המבנים מסוג מסוים, כמו שביחידה 8 הוכחנו טענה על כל המספרים הטבעיים. מבנה *בנוי* בכמה דרכים מוגדרות, ולכן ההוכחה מתפצלת לחלק לכל דרך: דרך בלי חלקים מאותו סוג היא *בסיס*, וכל דרך אחרת היא *צעד*, עם הנחת אינדוקציה לכל חלק מאותו סוג. הסטודנט רואה שהאינדוקציה של יחידה 8 היא מקרה פרטי (המספרים בנויים מ־0 ומ־n + 1), עובר על שלושה מבנים בסדר של ספרי הלימוד: רשימות (9.1–9.3), עצים בינאריים (9.4–9.6) ונוסחאות של לוגיקה (9.7–9.9), ולומד לבחור על איזה משתנה עושים אינדוקציה, לפתוח הגדרה עד שהנחת האינדוקציה מתאימה למטרה, ולהשתמש בשתי הנחות אינדוקציה באותו צעד.

**המקום של האינדוקציה המבנית בספרי הלימוד.** ב־Rosen (*Discrete Mathematics and Its Applications*) האינדוקציה המבנית באה מיד אחרי ההגדרות הרקורסיביות, באותו סעיף (Recursive Definitions and Structural Induction): קבוצה מוגדרת ב־basis step וב־recursive step, והוכחה עליה בנויה באותה צורה. הדוגמאות שם הן מחרוזות (האורך של שרשור), נוסחאות בנויות היטב ועצים בינאריים מלאים, וזה הסדר של היחידה. Enderton (*A Mathematical Introduction to Logic*) מציג את עקרון האינדוקציה לנוסחאות כבר בפרק הראשון: קבוצה שמכילה את הפסוקים וסגורה תחת הקשרים מכילה את כל הנוסחאות, ואחת הדוגמאות הראשונות היא שהסוגריים בכל נוסחה מאוזנים (שלב 9.7). Huth & Ryan (*Logic in Computer Science*) מוכיחים את אותה טענה על נוסחאות באינדוקציה על הגובה של עץ הניתוח שלהן. Logic and Proof, שעליו בנויה יחידה 8, מציג את המספרים הטבעיים כמבנה שבנוי מ־0 ומ־n + 1, ו־Theorem Proving in Lean ממשיך לטיפוסים אינדוקטיביים אחרים, רשימות ועצים, שהאינדוקציה עליהם היא אותו כלי; הוא מביא כתרגילים את השרשור עם [] ואת האסוציאטיביות של השרשור (9.1, 9.3) ואת האורך של שרשור (9.2). Natural Number Game, שעליו בנויה יחידה 8, הוא הדגם לפתיחת הגדרה ולהחלפה לפי הנחת האינדוקציה.

## המהלכים

ביחידה אין בלוק חדש: המהלך של יחידה 8, "נוכיח באינדוקציה על", מתאים את עצמו למבנה של השלב. בטבלה המהלכים כפי שהם נקראים אחרי שהם במקומם, עם דוגמאות מהשלבים; בסוגריים המרובעים מה שבוחרים מהרשימה.

| מהלך (כשהוא במקומו) | Lean | לפני → אחרי |
|---|---|---|
| **אינדוקציה על רשימה:** נוכיח באינדוקציה על [l]; בחלק הראשון "בסיס: נוכיח [] ++ [] = []", ובשני "צעד: נניח l ++ [] = l ונוכיח (a :: l) ++ [] = a :: l" | `induction l with`, ובחלקים `\| nil =>` ו־`\| cons a l _ =>` | `⊢ P(l)` ⟶ שני חלקים: `⊢ P([])`, ו־`P(l) ⊢ P(a :: l)` |
| **אינדוקציה על עץ:** נוכיח באינדוקציה על [t]; "בסיס: נוכיח leaves(leaf) = nodes(leaf) + 1", "צעד: נניח leaves(l) = nodes(l) + 1 ו־leaves(r) = nodes(r) + 1 ונוכיח leaves(node(l,r)) = nodes(node(l,r)) + 1" | `induction t with`, ובחלקים `\| leaf =>` ו־`\| node l r _ _ =>` | `⊢ P(t)` ⟶ שני חלקים: `⊢ P(leaf)`, ו־`P(l), P(r) ⊢ P(node(l,r))` |
| **אינדוקציה על נוסחה:** נוכיח באינדוקציה על [φ]; "בסיס: נוכיח opening(atom(i)) = closing(atom(i))", "צעד: נניח opening(φ) = closing(φ) ונוכיח opening(neg(φ)) = closing(neg(φ))", "צעד: נניח opening(φ) = closing(φ) ו־opening(ψ) = closing(ψ) ונוכיח opening(conj(φ,ψ)) = closing(conj(φ,ψ))" | `induction φ with`, ובחלקים `\| atom i =>`, `\| neg φ _ =>` ו־`\| conj φ ψ _ _ =>` (בשלב 9.9 גם `\| disj φ ψ _ _ =>` ו־`\| imp φ ψ _ _ =>`) | `⊢ P(φ)` ⟶ שלושה חלקים: `⊢ P(atom(i))`, `P(φ) ⊢ P(neg(φ))`, ו־`P(φ), P(ψ) ⊢ P(conj(φ,ψ))` |
| נשתמש בהגדרת [++] כדי לשכתב את [(a :: l) ++ []] בתוך [המטרה], ונקבל שצריך להוכיח a :: (l ++ []) = a :: l | `first \| rewrite [List.nil_append] \| rewrite [List.cons_append]` | `⊢ (a :: l) ++ [] = a :: l` ⟶ `⊢ a :: (l ++ []) = a :: l` |
| נשתמש בהגדרת [length] כדי לשכתב את [length([])] בתוך [המטרה], ונקבל שצריך להוכיח length(m) = 0 + length(m) | `rewrite [List.length]` | `⊢ length(m) = length([]) + length(m)` ⟶ `⊢ length(m) = 0 + length(m)` |
| נשתמש בהגדרת [mirror] כדי לשכתב את [mirror(node(l,r))] בתוך [המטרה], ונקבל שצריך להוכיח mirror(node(mirror(r),mirror(l))) = node(l,r) | `rewrite [mirror]` | `⊢ mirror(mirror(node(l,r))) = node(l,r)` ⟶ `⊢ mirror(node(mirror(r),mirror(l))) = node(l,r)` |

**מהלכים מיחידות קודמות** שבארגז של שלבים ביחידה הזאת:

| מהלך | Lean | לפני → אחרי | בשלבים |
|---|---|---|---|
| **שוויון לפי ההגדרה (יחידה 8):** שני הצדדים שווים לפי ההגדרה. | `rfl` | `⊢ [] ++ [] = []` ⟶ סגור | 9.1, 9.3, 9.4, 9.6–9.9 |
| **החלפה לפי שוויון (יחידה 8):** לפי הנחת האינדוקציה [l ++ [] = l] נחליף [את l ++ [] ב־l] בתוך [המטרה], ונקבל שצריך להוכיח a :: l = a :: l | `rewrite [‹l ++ [] = l›]` | `l ++ [] = l ⊢ a :: (l ++ []) = a :: l` ⟶ `l ++ [] = l ⊢ a :: l = a :: l` | 9.1–9.4, 9.6–9.9 |
| **חשבון (יחידה 8):** נכונות המטרה נובעת מחשבון פשוט. | `easylean_goal_only; omega` | `leaves(l) = nodes(l) + 1, leaves(r) = nodes(r) + 1 ⊢ nodes(l) + 1 + (nodes(r) + 1) = nodes(l) + nodes(r) + 1 + 1` ⟶ סגור, מהמטרה לבדה | 9.2, 9.4, 9.5, 9.8, 9.9 |
| **חשבון בעזרת ההנחות (יחידה 8):** נכונות המטרה נובעת מחשבון פשוט ומההנחות שבידינו. | `omega` | `height(l) ≤ nodes(l), height(r) ≤ nodes(r) ⊢ max(height(l),height(r)) + 1 ≤ nodes(l) + nodes(r) + 1` ⟶ סגור, בעזרת שתי ההנחות | 9.5 |
| **זה בדיוק (יחידה 0):** יש לנו ביד בדיוק את מה שאנחנו רוצים להוכיח. | `assumption` | `opening(φ) = closing(φ) ⊢ opening(φ) = closing(φ)` ⟶ סגור | 9.7–9.9 |

כמו ביחידה 8, החשבון מהמטרה לבדה מוציא קודם את כל מה שבידינו (`easylean_goal_only`), ולכן כדי להשתמש בהנחת אינדוקציה שהיא שוויון מחליפים לפיה במפורש. החשבון בעזרת ההנחות בארגז רק בשלב 9.5, שבו הנחות האינדוקציה הן אי־שוויונות.

ההגדרות שהיחידה משתמשת בהן, והשלב שבו כל אחת מופיעה לראשונה (ככרטיס בשלב):

| הגדרה (בתפריט של פתיחת ההגדרה, או כרטיס) | משוואות | מה Lean פותח | שלב |
|---|---|---|---|
| רשימות (כרטיס) | רשימה היא `[]`, או `a :: l` | `List` של Lean | 9.1 |
| ++ (כרטיס "שרשור") | `[] ++ m = m`, ו־`(a :: l) ++ m = a :: (l ++ m)` | `List.nil_append` או `List.cons_append`, הראשונה שמתאימה | 9.1 |
| length | `length([]) = 0`, ו־`length(a :: l) = length(l) + 1` | המשוואות של `List.length` | 9.2 |
| עצים בינאריים (כרטיס) | עץ הוא `leaf`, או `node(l,r)` | `inductive Tree` | 9.4 |
| leaves ו־nodes | `leaves(leaf) = 1`, `leaves(node(l,r)) = leaves(l) + leaves(r)`; `nodes(leaf) = 0`, `nodes(node(l,r)) = nodes(l) + nodes(r) + 1` | המשוואות של `leaves` ושל `nodes` | 9.4 |
| height | `height(leaf) = 0`, ו־`height(node(l,r)) = max(height(l),height(r)) + 1` | המשוואות של `height` | 9.5 |
| mirror | `mirror(leaf) = leaf`, ו־`mirror(node(l,r)) = node(mirror(r),mirror(l))` | המשוואות של `mirror` | 9.6 |
| נוסחאות (כרטיס) | נוסחה היא `atom(i)`, `neg(φ)` (נכתבת ¬φ) או `conj(φ,ψ)` (נכתבת (φ ∧ ψ)) | `inductive Formula` | 9.7 |
| opening ו־closing | `opening(atom(i)) = 0`, `opening(neg(φ)) = opening(φ)`, `opening(conj(φ,ψ)) = opening(φ) + opening(ψ) + 1`, וכך גם closing | המשוואות של `opening` ושל `closing` | 9.7 |
| atoms ו־binaries | `atoms(atom(i)) = 1`, `binaries(atom(i)) = 0`; ¬ לא משנה אף אחד מהם; `atoms(conj(φ,ψ)) = atoms(φ) + atoms(ψ)`, `binaries(conj(φ,ψ)) = binaries(φ) + binaries(ψ) + 1` | המשוואות של `atoms` ושל `binaries` | 9.8 |
| קשרים נוספים (כרטיס) | `disj(φ,ψ)` נכתבת (φ ∨ ψ), ו־`imp(φ,ψ)` נכתבת (φ → ψ); atoms ו־binaries מוגדרות עליהן כמו על conj | `inductive Formula` עם חמש דרכים | 9.9 |

**הוחלט: בלוק אינדוקציה אחד למספרים ולמבנים.** המהלך של יחידה 8, "נוכיח באינדוקציה על [t]", פותח עכשיו חלק לכל דרך לבנות את המבנה של השלב (`level.structure`: `Nat`, `List`, `Tree`, `Formula` או `Formula5`; ראו `STRUCTURES` ו־`setLevelStructure` ב־`frontend/src/blocks/moves.js`). דרך בלי חלקים מאותו סוג היא בסיס ("בסיס: נוכיח P(leaf)"); `atom(i)` היא בסיס, אף שיש לה חלק, כי i הוא מספר ולא נוסחה. כל דרך אחרת היא צעד, עם הנחת אינדוקציה לכל חלק מאותו סוג ("צעד: נניח P(l) ו־P(r) ונוכיח P(node(l,r))"). החלקים שהם מאותו סוג כמו המבנה שומרים על שם המשתנה (l ברשימה, φ בנוסחה), כמו שהצעד של יחידה 8 שומר על n; בעצים החלקים הם תמיד l ו־r, והחלק השני של נוסחה הוא ψ. יחידה 8 לא השתנתה: במבנה `Nat` הבלוק פותח בדיוק את שני החלקים שלה. כך הסטודנט לא לומד כלי חדש אלא רואה שאותו כלי עובד על כל מבנה, וזה גם מה שהספרים אומרים: האינדוקציה על המספרים היא אינדוקציה מבנית על המבנה 0, n + 1. מכיוון שהחלקים נפתחים לפי המבנה, אי אפשר לשכוח מקרה, ובראש כל חלק כתוב מה מוכיחים בו ומה מניחים.

**הוחלט: שלושה מבנים, בסדר של ספרי הלימוד.** רשימות (9.1–9.3), עצים בינאריים (9.4–9.6) ונוסחאות (9.7–9.9), כמו בסעיף של Rosen: מבנה עם צעד אחד והנחה אחת, אחר כך צעד עם שתי הנחות, ובסוף מבנה עם כמה צעדים שונים. בתכנית שאושרה, שלב 9.3 היה length(reverse(l)) = length(l), עם התוצאה של שלב קודם (length(l ++ m) = length(l) + length(m)) כהנחה. הוא הוחלף באסוציאטיביות של ++, כי השימוש בתוצאה הקודמת היה מחייב להקליד בשדה ביטויים כמו reverse(l) (כדי להציב אותם בתוצאה), ו־9.3 בנוי כולו מבחירה ברשימות.

**הוחלט: נוסחאות כעצמים נכתבות כפונקציות.** הנוסחאות שהוכחה מדברת עליהן נכתבות `atom(i)`, `neg(φ)`, `conj(φ,ψ)`, `disj(φ,ψ)` ו־`imp(φ,ψ)`, והכתיב המוכר (¬φ, (φ ∧ ψ)) מוסבר בטקסט ובכרטיסים. כך אין בלבול בין הנוסחאות שהן העצמים של ההוכחה לבין הטענות של ההוכחה עצמה: בשלבים 9.7–9.9 המטרה היא שוויון של מספרים, וה־∧ שבתוך נוסחה לא נראה כמו "וגם" שצריך להוכיח.

**מבנים ופונקציות משלנו.** כל מבנה והפונקציות עליו מוגדרים ב־Lean לפני ההוכחה (`STRUCTURE_PRELUDES` ב־`frontend/src/generator/lean.js`, לפי `level.structure`). הרשימות הן `List` של Lean עצמו, עם `++` ו־`List.length`, על איברים מטיפוס כלשהו α (`variable {α : Type}`). העצים (`Tree`, עם `leaf` ו־`node`) והנוסחאות (`Formula`, עם `atom`, `neg` ו־`conj`) מוגדרים בהקדמה כטיפוסים אינדוקטיביים, יחד עם leaves, nodes, height, mirror, opening, closing, atoms ו־binaries, כל אחת במשוואה לכל דרך. בשלב הבונוס לטיפוס הנוסחאות חמש דרכים (`Formula5`: גם `disj` ו־`imp`). בכל ההקדמות `set_option pp.fieldNotation false`, כדי ש־Lean ידפיס `node l r` ו־`List.length l` ולא `l.node r` או `l.length`.

**תצוגה.** כמו ביחידה 8, פונקציות מוצגות כמופעלות על הארגומנטים שלהן (`writeApplications` ב־`frontend/src/game/formatProofGoal.js`): `node(l,r)`, `length(l)`, `mirror(mirror(t))`, `max(height(l),height(r))`, ו־`List.length` נכתבת `length`. גם הדרכים לבנות מבנה (`node`, `atom`, `neg`, `conj`, `disj`, `imp`) נכתבות כך.

**פתיחת הגדרה.** המהלך "נשתמש בהגדרת [f] כדי לשכתב את [חלק] בתוך [המטרה]" (`FUNCTIONS` ו־`FieldFunction` ב־`moves.js`) מציע בתפריט את הפונקציות של המבנה של השלב: ++ ו־length ברשימות; leaves, nodes, height ו־mirror בעצים; opening, closing, atoms ו־binaries בנוסחאות. את ++ פותחים לפי `List.nil_append` או `List.cons_append`, הראשונה שמתאימה (`first | rewrite [List.nil_append] | rewrite [List.cons_append]`), ואת שאר הפונקציות לפי המשוואות שלהן (`rewrite [mirror]`). בוחרים בו אם לפתוח במטרה או בטענה שבידינו (בטענה שבידינו הפתיחה נעשית בעותק, והתוצאה מצטרפת להנחות), אבל לא את המקום בתוכה: המהלך פותח במקום הראשון שבו ההגדרה מתאימה (ובכל מקום שבו מופיע אותו ביטוי בדיוק). כמו ההחלפה, הוא כותב מה התקבל: "ונקבל שצריך להוכיח X" במטרה, "ונקבל Y" בטענה שבידינו, ולכן בפתרונות שלהלן התוצאה כתובה כחלק מהמהלך.

**הנחות האינדוקציה.** ב־Lean לכל דרך יש חלק: `| nil =>`, `| cons a l _ =>`, `| leaf =>`, `| node l r _ _ =>`, `| atom i =>`, `| neg φ _ =>`, `| conj φ ψ _ _ =>`. להנחות האינדוקציה אין שמות (`_`), ומשתמשים בהן לפי מה שהן אומרות, כמו בכל הנחה: בהחלפה בוחרים את השוויון מהרשימה, ו"יש לנו ביד" והחשבון בעזרת ההנחות מוצאים אותן בעצמם. החשבון מהמטרה לבדה לא משתמש בהן.

## שלבים

לכל שלב: מה לומדים בו, למה הוא בנוי כך, איך אנחנו רוצים שסטודנטים יפתרו אותו, ושיקולים ושאלות שעוד צריך להכריע. צילומי הפתרונות נוצרים מ־`frontend/e2e/solutions.js` (ראו [יחידה 0](00-getting-started.md#שלבים)).

**סדר היחידה.** רשימות (9.1–9.3): מבנה עם צעד אחד והנחת אינדוקציה אחת, הכי קרוב ליחידה 8; קודם טענה שמקבילה ל־0 + n = n, אחר כך בחירה של המשתנה, ואחר כך פתיחה של הגדרה כמה פעמים. עצים (9.4–9.6): שתי הנחות אינדוקציה בכל צעד, פעם בחשבון ופעם בהחלפה. נוסחאות (9.7–9.9): כמה צעדים שונים, עם הנחה אחת או עם שתיים, ובבונוס חמש דרכים לבנות נוסחה.

### שלב 9.1: אינדוקציה על רשימות

`⊢ l ++ [] = l` · עצמים: l (רשימה) · בארגז: אינדוקציה, פתיחת הגדרה, החלפה לפי שוויון, שוויון לפי ההגדרה

**מה לומדים.** שאינדוקציה היא לא רק על מספרים: מבנה שבנוי בשתי דרכים נותן הוכחה בשני חלקים, בסיס וצעד. ורשימות, עם השרשור שמוגדר לפי הרשימה הראשונה.

**למה כך.** טקסט הפתיחה מתחיל מיחידה 8 (המספרים בנויים מ־0 ומ־n + 1) ומעביר את אותו רעיון לרשימות. הטענה מקבילה ל־0 + n = n של שלב 8.6: השרשור עם [] משמאל נכון לפי ההגדרה, אבל מימין הוא דורש אינדוקציה, והטקסט אומר זאת. גם המהלכים הם בדיוק של 8.6 (פתיחת הגדרה, החלפה לפי הנחת האינדוקציה, שוויון לפי ההגדרה), כך שהדבר החדש היחיד הוא המבנה. אין חשבון בארגז, ולכן משתמשים בהנחת האינדוקציה במפורש. זה אחד התרגילים על רשימות ב־Theorem Proving in Lean.

**פתרון.** "נוכיח באינדוקציה על l." בחלק "בסיס: נוכיח [] ++ [] = []": "שני הצדדים שווים לפי ההגדרה." בחלק "צעד: נניח l ++ [] = l ונוכיח (a :: l) ++ [] = a :: l": "נשתמש בהגדרת ++ כדי לשכתב את (a :: l) ++ [] בתוך המטרה, ונקבל שצריך להוכיח a :: (l ++ []) = a :: l"; "לפי הנחת האינדוקציה l ++ [] = l נחליף את l ++ [] ב־l בתוך המטרה, ונקבל שצריך להוכיח a :: l = a :: l"; ו"שני הצדדים שווים לפי ההגדרה."

![שלב 9.1](images/unit9-level1-a.png)

**שיקולים ושאלות להכרעה.**
- בצעד מופיע איבר חדש, a, שלא הוצג: הכותרת אומרת "ונוכיח (a :: l) ++ [] = a :: l" בלי "יהי a איבר". ביחידה 4 הקפדנו להציג כל עצם חדש. האם לכתוב בכותרת "לכל איבר a", או להוסיף את a לשורת העצמים של החלק?
- כמו ביחידה 8, ה־l שבצעד הוא הזנב של הרשימה, ולא ה־l של המטרה (ראו "שם המשתנה בצעד" ביחידה 8). ברשימות זה בולט יותר, כי ה־l של המטרה הוא a :: l.
- הוחלט: צד שלם של שוויון נכתב בלי סוגריים משלו, ולכן הכותרת של הצעד היא "ונוכיח (a :: l) ++ [] = a :: l", כמו ברמז. הסוגריים סביב a :: l בצד שמאל נשארים: הם מראים שהשרשור הוא של כל הרשימה a :: l.
- בתפריט של פתיחת ההגדרה כבר יש length, שמוצגת רק בשלב 9.2 (ראו שאלה (ה) בסוף).

### שלב 9.2: האורך של שרשור

`⊢ length(l ++ m) = length(l) + length(m)` · עצמים: l, m (רשימות) · בארגז: אינדוקציה, פתיחת הגדרה, החלפה לפי שוויון, חשבון

**מה לומדים.** לבחור את המשתנה של האינדוקציה: את הרשימה שההגדרות "מפרקות" (l, כי ++ מוגדר לפי הרשימה הראשונה), כשהשנייה (m) נשארת קבועה. ופונקציה שנייה, length, שגם היא מוגדרת לפי מבנה הרשימה.

**למה כך.** זו הדוגמה של Rosen למחרוזות (האורך של שרשור הוא סכום האורכים), ותרגיל ב־Theorem Proving in Lean. ברשימת המשתנים של האינדוקציה יש גם l וגם m, והטקסט מסביר למה בוחרים ב־l. בצעד פותחים שלוש פעמים, ורואים שכל פתיחה מפרקת מקום אחר במטרה. אחרי הפתיחות length(l ++ m) מופיע במטרה, כמו בהנחת האינדוקציה: מחליפים לפיה במפורש, ואת השאר משלים החשבון מהמטרה לבדה (ראו שאלה (א) בסוף).

**פתרון.** "נוכיח באינדוקציה על l." בחלק "בסיס: נוכיח length([] ++ m) = length([]) + length(m)": "נשתמש בהגדרת ++ כדי לשכתב את [] ++ m בתוך המטרה, ונקבל שצריך להוכיח length(m) = length([]) + length(m)"; "נשתמש בהגדרת length כדי לשכתב את length([]) בתוך המטרה, ונקבל שצריך להוכיח length(m) = 0 + length(m)"; "נכונות המטרה נובעת מחשבון פשוט." בחלק "צעד: נניח length(l ++ m) = length(l) + length(m) ונוכיח length((a :: l) ++ m) = length(a :: l) + length(m)": "נשתמש בהגדרת ++ כדי לשכתב את (a :: l) ++ m בתוך המטרה, ונקבל שצריך להוכיח length(a :: (l ++ m)) = length(a :: l) + length(m)"; "נשתמש בהגדרת length כדי לשכתב את length(a :: (l ++ m)) בתוך המטרה, ונקבל שצריך להוכיח length(l ++ m) + 1 = length(a :: l) + length(m)"; "נשתמש בהגדרת length כדי לשכתב את length(a :: l) בתוך המטרה, ונקבל שצריך להוכיח length(l ++ m) + 1 = length(l) + 1 + length(m)"; "לפי הנחת האינדוקציה length(l ++ m) = length(l) + length(m) נחליף את length(l ++ m) ב־length(l) + length(m) בתוך המטרה, ונקבל שצריך להוכיח length(l) + length(m) + 1 = length(l) + 1 + length(m)"; ו"נכונות המטרה נובעת מחשבון פשוט."

![שלב 9.2](images/unit9-level2-a.png)

**שיקולים ושאלות להכרעה.**
- אם הסטודנט בוחר ב־m, הכותרות נכונות (בסיס על length(l ++ []), צעד על length(l ++ (a :: m))), אבל אחר כך אי אפשר לפתוח את ++, כי l אינה [] ואינה מהצורה a :: …. כדאי לבדוק מה ההסבר אומר אז, ואם הוא מכוון לבחירה במשתנה האחר. זו הטעות שהשלב בנוי סביבה, ולכן ייתכן שכדאי שהשלב יתחיל בה (או שהרמז יזהיר ממנה).
- את length פותחים פעמיים, ולא בוחרים איפה: המהלך פותח במקום הראשון ש־Lean מוצא. הרמז אומר "פעם בצד שמאל ופעם בצד ימין", והסטודנט לא יודע מראש איזה צד ייפתח קודם. זה לא משנה את ההוכחה, אבל אולי מבלבל.
- גם בבסיס צריך לפתוח את שתי ההגדרות: החשבון לא פותח הגדרות, ו־length([]) הוא בשבילו מספר לא ידוע.

### שלב 9.3: השרשור אסוציאטיבי

`⊢ l ++ (m ++ k) = (l ++ m) ++ k` · עצמים: l, m, k (רשימות) · בארגז: אינדוקציה, פתיחת הגדרה, החלפה לפי שוויון, שוויון לפי ההגדרה

**מה לומדים.** לפתוח הגדרה כמה פעמים, עד שהנחת האינדוקציה מתאימה למה שנשאר להוכיח, ואז להחליף לפיה במפורש.

**למה כך.** האסוציאטיביות של השרשור, כמו של החיבור ב־Natural Number Game, היא תרגיל נוסף על רשימות ב־Theorem Proving in Lean. היא החליפה את length(reverse(l)) = length(l) של התכנית המקורית (ראו ההחלטה בתחילת המסמך). בבסיס [] משמאל, ולכן שני הצדדים שווים לפי ההגדרה בלי לפתוח דבר; בצעד a :: l מופיעה משמאל לשלושה שרשורים, וכל פתיחה מוציאה את a החוצה מאחד מהם. אין חשבון בארגז, ולכן ההחלפה לפי הנחת האינדוקציה היא חלק הכרחי מההוכחה.

**פתרון.** "נוכיח באינדוקציה על l." בחלק "בסיס: נוכיח [] ++ (m ++ k) = ([] ++ m) ++ k": "שני הצדדים שווים לפי ההגדרה." בחלק "צעד: נניח l ++ (m ++ k) = (l ++ m) ++ k ונוכיח (a :: l) ++ (m ++ k) = ((a :: l) ++ m) ++ k": שכתוב לפי הגדרת ++, חלק אחר חלק: "נשתמש בהגדרת ++ כדי לשכתב את (a :: l) ++ (m ++ k) בתוך המטרה, ונקבל שצריך להוכיח a :: (l ++ (m ++ k)) = ((a :: l) ++ m) ++ k"; "נשתמש בהגדרת ++ כדי לשכתב את (a :: l) ++ m בתוך המטרה, ונקבל שצריך להוכיח a :: (l ++ (m ++ k)) = (a :: (l ++ m)) ++ k"; "נשתמש בהגדרת ++ כדי לשכתב את (a :: (l ++ m)) ++ k בתוך המטרה, ונקבל שצריך להוכיח a :: (l ++ (m ++ k)) = a :: ((l ++ m) ++ k)"; "לפי הנחת האינדוקציה l ++ (m ++ k) = (l ++ m) ++ k נחליף את l ++ (m ++ k) ב־(l ++ m) ++ k בתוך המטרה, ונקבל שצריך להוכיח a :: ((l ++ m) ++ k) = a :: ((l ++ m) ++ k)"; ו"שני הצדדים שווים לפי ההגדרה."

![שלב 9.3](images/unit9-level3-a.png)
**שיקולים ושאלות להכרעה.**
- Lean כותב (l ++ m) ++ k בלי סוגריים, l ++ m ++ k, כי ++ נקרא משמאל לימין. הוחלט שהתצוגה תכתוב את הסוגריים של כל שרשור שהוא צד של שרשור אחר, ושל a :: l שהוא צד של שרשור, ולכן הכותרות, רשימת השוויונות וההחלפה כתובות "(l ++ m) ++ k", כמו בלוק המטרה. בשלב שכל העניין בו הוא איפה הסוגריים, זה הכרחי.
- הצעד דורש שלושה שכתובים לפי ההגדרה של ++, ובכל אחד בוחרים חלק אחר. הוחלט (עם מחבר הקורס) לא להציע "כל החלקים": הספירה עצמה מלמדת, כי כל שכתוב מוציא a :: החוצה משרשור אחד, וההוכחה אומרת בדיוק מה משוכתב.
- השלב המקורי, על reverse, יכול לחזור אם יהיה מנגנון להשתמש בטענות שכבר הוכחו (ראו "טענות שכבר הוכחו" ביחידה 8).

### שלב 9.4: עצים: עלים וצמתים

`⊢ leaves(t) = nodes(t) + 1` · עצמים: t (עץ) · בארגז: אינדוקציה, פתיחת הגדרה, החלפה לפי שוויון, שוויון לפי ההגדרה, חשבון

**מה לומדים.** עצים בינאריים, וצעד עם *שתי* הנחות אינדוקציה, אחת לכל ילד.

**למה כך.** העצים כאן הם העצים הבינאריים המלאים של Rosen (עלה, או שורש חדש ששני הילדים שלו הם עצים), ו־nodes סופרת את הצמתים הפנימיים בלבד. הטענה שבעץ בינארי מלא יש עלה אחד יותר מצמתים פנימיים היא מהקלסיות. הבלוק כותב את שתי ההנחות בכותרת של הצעד, כך שהסטודנט רואה שהן שתיים לפני שהוא מתחיל. אחרי הפתיחה leaves(l) ו־leaves(r) מופיעים במטרה, ומחליפים לפי כל אחת משתי ההנחות במפורש; את השאר משלים החשבון מהמטרה לבדה.

**פתרון.** "נוכיח באינדוקציה על t." בחלק "בסיס: נוכיח leaves(leaf) = nodes(leaf) + 1": "שני הצדדים שווים לפי ההגדרה." (1 = 0 + 1). בחלק "צעד: נניח leaves(l) = nodes(l) + 1 ו־leaves(r) = nodes(r) + 1 ונוכיח leaves(node(l,r)) = nodes(node(l,r)) + 1": "נשתמש בהגדרת leaves כדי לשכתב את leaves(node(l,r)) בתוך המטרה, ונקבל שצריך להוכיח leaves(l) + leaves(r) = nodes(node(l,r)) + 1"; "נשתמש בהגדרת nodes כדי לשכתב את nodes(node(l,r)) בתוך המטרה, ונקבל שצריך להוכיח leaves(l) + leaves(r) = nodes(l) + nodes(r) + 1 + 1"; "לפי הנחת האינדוקציה leaves(l) = nodes(l) + 1 נחליף את leaves(l) ב־nodes(l) + 1 בתוך המטרה, ונקבל שצריך להוכיח nodes(l) + 1 + leaves(r) = nodes(l) + nodes(r) + 1 + 1"; "לפי הנחת האינדוקציה leaves(r) = nodes(r) + 1 נחליף את leaves(r) ב־nodes(r) + 1 בתוך המטרה, ונקבל שצריך להוכיח nodes(l) + 1 + (nodes(r) + 1) = nodes(l) + nodes(r) + 1 + 1"; ו"נכונות המטרה נובעת מחשבון פשוט."

![שלב 9.4](images/unit9-level4-a.png)

**שיקולים ושאלות להכרעה.**
- השם nodes סופר רק צמתים פנימיים, ואילו בתורת הגרפים גם עלה הוא צומת (vertex). הכרטיס מגדיר את nodes במדויק, אבל השם עלול להטעות. אפשרות: internal, או "צמתים פנימיים" בטקסט.
- הוחלט: שתי הנחות האינדוקציה מופיעות בהוכחה, כל אחת בהחלפה משלה, כמו בשלב 9.6, והחשבון הוא מהמטרה לבדה (ראו שאלה (א)). השלב בא לפני 9.6, ולכן הוא הראשון ביחידה שבו מחליפים לפי שתי הנחות.
- בתפריט של פתיחת ההגדרה כבר יש height ו־mirror (ראו שאלה (ה)).

### שלב 9.5: הגובה

`⊢ height(t) ≤ nodes(t)` · עצמים: t (עץ) · בארגז: אינדוקציה, פתיחת הגדרה, חשבון, חשבון בעזרת ההנחות

**מה לומדים.** אינדוקציה מבנית שמוכיחה אי־שוויון, ופונקציה שמשתמשת ב־max.

**למה כך.** Rosen מוכיח על עצים בינאריים מלאים אי־שוויון בין מספר הצמתים לגובה (עם חזקה של 2). כאן הגרסה הלינארית, שהחשבון יודע לסגור (הוא מכיר את max), כדי שהעיקר יהיה המבנה של ההוכחה ולא האלגברה. כמו בשלב 8.8, הנחות האינדוקציה הן אי־שוויונות, ואין מה להחליף לפיהן: בצעד משתמשים בהן בחשבון בעזרת ההנחות, וטקסט הפתיחה אומר זאת. בבסיס אין הנחות, ומספיק החשבון מהמטרה לבדה. גם בבסיס פותחים הגדרה, כי החשבון לא יודע מה height(leaf).

**פתרון.** "נוכיח באינדוקציה על t." בחלק "בסיס: נוכיח height(leaf) ≤ nodes(leaf)": "נשתמש בהגדרת height כדי לשכתב את height(leaf) בתוך המטרה, ונקבל שצריך להוכיח 0 ≤ nodes(leaf)"; "נשתמש בהגדרת nodes כדי לשכתב את nodes(leaf) בתוך המטרה, ונקבל שצריך להוכיח 0 ≤ 0"; "נכונות המטרה נובעת מחשבון פשוט." בחלק "צעד: נניח height(l) ≤ nodes(l) ו־height(r) ≤ nodes(r) ונוכיח height(node(l,r)) ≤ nodes(node(l,r))": "נשתמש בהגדרת height כדי לשכתב את height(node(l,r)) בתוך המטרה, ונקבל שצריך להוכיח max(height(l),height(r)) + 1 ≤ nodes(node(l,r))"; "נשתמש בהגדרת nodes כדי לשכתב את nodes(node(l,r)) בתוך המטרה, ונקבל שצריך להוכיח max(height(l),height(r)) + 1 ≤ nodes(l) + nodes(r) + 1"; ו"נכונות המטרה נובעת מחשבון פשוט ומהנחות האינדוקציה."

![שלב 9.5](images/unit9-level5-a.png)

**שיקולים ושאלות להכרעה.**
- בבסיס, אחרי פתיחת height, המטרה היא 0 ≤ nodes(leaf), וזה נכון לכל מספר טבעי; החשבון צפוי לסגור אותה בלי לפתוח את nodes (לא נבדק ב־Lean). הרמז והפתרון פותחים את שתיהן.
- שני מהלכי החשבון בארגז, ולכן הסטודנט יכול לסגור גם את הבסיס בחשבון בעזרת ההנחות. אין בזה נזק (בבסיס אין הנחות), אבל ההבחנה בין שני המהלכים לא נבדקת כאן, כמו בשלב 8.8.
- הטענה חלשה (הגובה לא גדול ממספר הצמתים). הטענה הקלסית, nodes(t) + 1 ≤ 2^height(t) או leaves(t) ≤ 2^height(t), דורשת אלגברה עם חזקה, ויכולה להיות שלב בונוס על עצים (עם מהלך האלגברה בעזרת ההנחות של יחידה 8, כי הנחות האינדוקציה שם הן אי־שוויונות, אם הוא מצליח בה).

### שלב 9.6: מראה של מראה

`⊢ mirror(mirror(t)) = t` · עצמים: t (עץ) · בארגז: אינדוקציה, פתיחת הגדרה, החלפה לפי שוויון, שוויון לפי ההגדרה

**מה לומדים.** פונקציה שהתוצאה שלה היא מבנה ולא מספר, ושימוש מפורש בכל אחת משתי הנחות האינדוקציה.

**למה כך.** אין כאן חשבון: כל צעד הוא פתיחת הגדרה, החלפה או שוויון לפי ההגדרה, כמו ב־9.1 וב־8.6. כמו ב־9.4, כל אחת משתי ההנחות מופיעה בהחלפה משלה, אבל כאן מה שנשאר אחרי ההחלפות הוא שוויון של עצים, ששני צדדיו זהים. את mirror פותחים פעמיים: קודם את הפנימית (היא זו שמופעלת על node(l,r)), ואז את החיצונית, שעכשיו מופעלת על node.

**פתרון.** "נוכיח באינדוקציה על t." בחלק "בסיס: נוכיח mirror(mirror(leaf)) = leaf": "שני הצדדים שווים לפי ההגדרה." בחלק "צעד: נניח mirror(mirror(l)) = l ו־mirror(mirror(r)) = r ונוכיח mirror(mirror(node(l,r))) = node(l,r)": "נשתמש בהגדרת mirror כדי לשכתב את mirror(node(l,r)) בתוך המטרה, ונקבל שצריך להוכיח mirror(node(mirror(r),mirror(l))) = node(l,r)"; "נשתמש בהגדרת mirror כדי לשכתב את mirror(node(mirror(r),mirror(l))) בתוך המטרה, ונקבל שצריך להוכיח node(mirror(mirror(l)),mirror(mirror(r))) = node(l,r)"; "לפי הנחת האינדוקציה mirror(mirror(l)) = l נחליף את mirror(mirror(l)) ב־l בתוך המטרה, ונקבל שצריך להוכיח node(l,mirror(mirror(r))) = node(l,r)"; "לפי הנחת האינדוקציה mirror(mirror(r)) = r נחליף את mirror(mirror(r)) ב־r בתוך המטרה, ונקבל שצריך להוכיח node(l,r) = node(l,r)"; ו"שני הצדדים שווים לפי ההגדרה."

![שלב 9.6](images/unit9-level6-a.png)
**שיקולים ושאלות להכרעה.**
- הפתיחה הראשונה נעשית בתוך המטרה (ב־mirror הפנימית), ולא בחוץ, כי רק שם ההגדרה מתאימה. הסטודנט לא בוחר את המקום, ואולי מצפה לפתיחה מבחוץ. כדאי שהרמז יאמר מה מתקבל אחרי הפתיחה הראשונה, ולא רק אחרי השנייה.
- שתי החלפות לפי שתי הנחות שונות, כמו ב־9.4. ההבדל בין mirror(mirror(l)) = l ל־mirror(mirror(r)) = r ברשימה הוא אות אחת; צריך לבדוק שהתפריט קריא.

### שלב 9.7: נוסחאות: סוגריים מאוזנים

`⊢ opening(φ) = closing(φ)` · עצמים: φ (נוסחה) · בארגז: אינדוקציה, פתיחת הגדרה, החלפה לפי שוויון, שוויון לפי ההגדרה, יש לנו ביד

**מה לומדים.** שנוסחאות של לוגיקה הן מבנה בנוי (פסוקים, ושלילה ו"וגם" של נוסחאות), ואינדוקציה עם שלושה חלקים: בסיס, צעד עם הנחה אחת (¬) וצעד עם שתי הנחות (∧). וההבחנה בין הנוסחאות שההוכחה מדברת עליהן לבין הטענות של ההוכחה עצמה.

**למה כך.** הסוגריים המאוזנים הם הדוגמה הראשונה של Enderton לעקרון האינדוקציה על נוסחאות, והטענה מופיעה גם ב־Huth & Ryan ובתרגילים של Rosen. הנוסחאות כתובות כפונקציות (ההחלטה בתחילת המסמך), והטקסט מסביר שהן נכתבות ¬φ ו־(φ ∧ ψ), כך ש־opening ו־closing סופרות את הסוגריים של הכתיב: ∧ מוסיף זוג, ¬ לא מוסיף. כדי שיהיו רק שלושה חלקים, יש רק ¬ ו־∧; שאר הקשרים בבונוס. בצעד של ¬, אחרי הפתיחה, נשארת בדיוק הנחת האינדוקציה, ו"יש לנו ביד" סוגר: הנחת האינדוקציה היא הנחה רגילה. בצעד של ∧, אחרי הפתיחה, opening(φ) ו־opening(ψ) מופיעים במטרה, ומחליפים לפי שתי הנחות האינדוקציה, כמו ב־9.4; אחרי ההחלפות שני הצדדים זהים, ולכן אין צורך בחשבון, ואין חשבון בארגז.

**פתרון.** "נוכיח באינדוקציה על φ." בחלק "בסיס: נוכיח opening(atom(i)) = closing(atom(i))": "שני הצדדים שווים לפי ההגדרה." בחלק "צעד: נניח opening(φ) = closing(φ) ונוכיח opening(neg(φ)) = closing(neg(φ))": "נשתמש בהגדרת opening כדי לשכתב את opening(neg(φ)) בתוך המטרה, ונקבל שצריך להוכיח opening(φ) = closing(neg(φ))"; "נשתמש בהגדרת closing כדי לשכתב את closing(neg(φ)) בתוך המטרה, ונקבל שצריך להוכיח opening(φ) = closing(φ)"; "זו בדיוק הנחת האינדוקציה." בחלק "צעד: נניח opening(φ) = closing(φ) ו־opening(ψ) = closing(ψ) ונוכיח opening(conj(φ,ψ)) = closing(conj(φ,ψ))": פותחים את opening ואת closing, ונקבל שצריך להוכיח opening(φ) + opening(ψ) + 1 = closing(φ) + closing(ψ) + 1; "לפי הנחת האינדוקציה opening(φ) = closing(φ) נחליף את opening(φ) ב־closing(φ) בתוך המטרה"; "לפי הנחת האינדוקציה opening(ψ) = closing(ψ) נחליף את opening(ψ) ב־closing(ψ) בתוך המטרה, ונקבל שצריך להוכיח closing(φ) + closing(ψ) + 1 = closing(φ) + closing(ψ) + 1"; ו"שני הצדדים שווים לפי ההגדרה."

![שלב 9.7](images/unit9-level7-a.png)

**שיקולים ושאלות להכרעה.**
- הקשר בין conj(φ,ψ) לבין הכתיב (φ ∧ ψ) נמצא רק בטקסט ובכרטיס, ו־opening מוגדרת על הכתיב הזה. דוגמה מפורשת, למשל opening(conj(atom(1),neg(atom(2)))) = 1 עבור (p₁ ∧ ¬p₂), תעזור לראות מה נספר.
- בצעד של ¬ יש עכשיו שתי דרכים, ושתיהן משתמשות בהנחת האינדוקציה במפורש: "יש לנו ביד", או החלפה לפי ההנחה (את opening(φ) ב־closing(φ)) ואחריה "שני הצדדים שווים לפי ההגדרה". הרמז מתאר את הראשונה.
- בבסיס מופיע מספר חדש, i (האינדקס של הפסוק), שלא הוצג. כמו a בשלב 9.1.
- בתפריט של פתיחת ההגדרה כבר יש atoms ו־binaries (ראו שאלה (ה)).

### שלב 9.8: פסוקים וקשרים

`⊢ atoms(φ) = binaries(φ) + 1` · עצמים: φ (נוסחה) · בארגז: אינדוקציה, פתיחת הגדרה, החלפה לפי שוויון, שוויון לפי ההגדרה, יש לנו ביד, חשבון

**מה לומדים.** אותו מבנה של הוכחה על תכונה אחרת, ושנוסחה היא מעין עץ: הפסוקים הם העלים, והקשרים הבינאריים הם הצמתים.

**למה כך.** הטענה היא שלב 9.4 בשפה של נוסחאות (atoms במקום leaves, binaries במקום nodes), והטקסט אומר זאת. ¬ הוא צומת עם ילד אחד, שלא משנה אף אחד מהמספרים, ולכן הצעד שלו נסגר בהנחת האינדוקציה, כמו ב־9.7. בצעד של ∧ מחליפים לפי שתי הנחות האינדוקציה, כמו ב־9.4, ואת השאר משלים החשבון מהמטרה לבדה. Rosen מביא טענות כאלה על נוסחאות כתרגילים לאינדוקציה מבנית.

**פתרון.** "נוכיח באינדוקציה על φ." בחלק "בסיס: נוכיח atoms(atom(i)) = binaries(atom(i)) + 1": "שני הצדדים שווים לפי ההגדרה." בחלק "צעד: נניח atoms(φ) = binaries(φ) + 1 ונוכיח atoms(neg(φ)) = binaries(neg(φ)) + 1": פותחים את atoms ואת binaries, ונקבל שצריך להוכיח atoms(φ) = binaries(φ) + 1; ו"זו בדיוק הנחת האינדוקציה." בחלק "צעד: נניח atoms(φ) = binaries(φ) + 1 ו־atoms(ψ) = binaries(ψ) + 1 ונוכיח atoms(conj(φ,ψ)) = binaries(conj(φ,ψ)) + 1": פותחים את atoms ואת binaries, ונקבל שצריך להוכיח atoms(φ) + atoms(ψ) = binaries(φ) + binaries(ψ) + 1 + 1; "לפי הנחת האינדוקציה atoms(φ) = binaries(φ) + 1 נחליף את atoms(φ) ב־binaries(φ) + 1 בתוך המטרה"; "לפי הנחת האינדוקציה atoms(ψ) = binaries(ψ) + 1 נחליף את atoms(ψ) ב־binaries(ψ) + 1 בתוך המטרה, ונקבל שצריך להוכיח binaries(φ) + 1 + (binaries(ψ) + 1) = binaries(φ) + binaries(ψ) + 1 + 1"; ו"נכונות המטרה נובעת מחשבון פשוט."

![שלב 9.8](images/unit9-level8-a.png)

**שיקולים ושאלות להכרעה.**
- ההוכחה כמעט זהה בצורתה ל־9.7: אותם מהלכים באותו סדר, ורק הסוף של הצעד של ∧ שונה (חשבון במקום "שני הצדדים שווים לפי ההגדרה").
- בצעד של ¬ אפשר, כמו ב־9.7, להחליף לפי הנחת האינדוקציה ואז "שני הצדדים שווים לפי ההגדרה", במקום "יש לנו ביד". החשבון מהמטרה לבדה לא סוגר אותו, כי בלי ההנחה atoms(φ) = binaries(φ) + 1 אינה עובדה של חשבון. אפשר להחליף את השלב בטענה שבה הצעד של ¬ אינו טריוויאלי (למשל מספר הסימנים בכתיב, שבו ¬ מוסיף 1), או בפונקציה מנוסחאות לנוסחאות, כמו mirror בעצים (למשל החלפת ∧ ב־∨ ושמירה על מספר הפסוקים).
- טקסט הפתיחה כתוב עם דוגמה בכתיב הרגיל, (p₁ ∧ ¬p₂), ולא בכתיב הפונקציות. זה מכוון (הכתיב המוכר), אבל זה המקום היחיד שבו הכתיב הרגיל מופיע בלי התרגום שלו.

### שלב 9.9: שלב בונוס: כל הקשרים

`⊢ atoms(φ) = binaries(φ) + 1` · עצמים: φ (נוסחה, עם ∨ ו־→) · בארגז: אינדוקציה, פתיחת הגדרה, החלפה לפי שוויון, שוויון לפי ההגדרה, יש לנו ביד, חשבון

**מה לומדים.** שמספר החלקים של האינדוקציה נקבע לפי מספר הדרכים לבנות את המבנה: כשמוסיפים קשר לשפה, מוסיפים צעד להוכחה.

**למה כך.** אותה טענה כמו ב־9.8, כך שהדבר היחיד שמשתנה הוא המבנה (`Formula5`, עם `disj` ו־`imp`), והבלוק פותח חמישה חלקים במקום שלושה. אצל Rosen ואצל Enderton הנוסחאות בנויות מכל הקשרים, וכך רואים שההוכחה של 9.8 לא "תלויה" במקרה שיש רק ∧.

**פתרון.** "נוכיח באינדוקציה על φ." בבסיס ("נוכיח atoms(atom(i)) = binaries(atom(i)) + 1"): "שני הצדדים שווים לפי ההגדרה." בצעד של ¬: פותחים את atoms ואת binaries, ו"זו בדיוק הנחת האינדוקציה." בשלושת הצעדים של conj, disj ו־imp (למשל "צעד: נניח atoms(φ) = binaries(φ) + 1 ו־atoms(ψ) = binaries(ψ) + 1 ונוכיח atoms(disj(φ,ψ)) = binaries(disj(φ,ψ)) + 1"): פותחים את atoms ואת binaries; "לפי הנחת האינדוקציה atoms(φ) = binaries(φ) + 1 נחליף את atoms(φ) ב־binaries(φ) + 1 בתוך המטרה"; "לפי הנחת האינדוקציה atoms(ψ) = binaries(ψ) + 1 נחליף את atoms(ψ) ב־binaries(ψ) + 1 בתוך המטרה"; ו"נכונות המטרה נובעת מחשבון פשוט.", כמו בצעד של ∧ בשלב 9.8.

![שלב 9.9](images/unit9-level9-a.png)

**שיקולים ושאלות להכרעה.**
- שלושה צעדים זהים, חמישה־עשר בלוקים שחוזרים על עצמם (בכל צעד שתי פתיחות, שתי החלפות וחשבון). בספרים כותבים "המקרים של ∨ ושל → דומים". אפשרות: מהלך שמעתיק הוכחה של חלק לחלקים האחרים, או הוכחה אחת לכל הקשרים הבינאריים (ב־Lean, `<;>` או `all_goals`). המחיר: הסטודנט לא רואה שכל חלק נבדק.
- אין ↔. Enderton כולל אותו בין חמשת הקשרים שלו; כאן החמישה הם הפסוק, ¬ ושלושה קשרים בינאריים. אם מוסיפים ↔, יש צעד שישי זהה.

**הנחת האינדוקציה בשמה.** הוחלט (לבקשת מחבר הקורס) שמהלך שמשתמש בהנחת האינדוקציה יאמר זאת, כמו בהוכחה כתובה: החלפה לפיה נכתבת "לפי הנחת האינדוקציה … נחליף …" (במקום "לפי השוויון"), סיום שהמטרה בו היא ההנחה נכתב "זו בדיוק הנחת האינדוקציה.", וחשבון או אלגברה כשההנחות היחידות שבידינו הן הנחות האינדוקציה נכתבים "… ומהנחות האינדוקציה." (או "ומהנחת", כשיש אחת). הבלוק מזהה את ההנחות לפי הכותרת של החלק "צעד" שהוא נמצא בו; מחוץ לאינדוקציה הניסוח לא משתנה.

## שאלות שנוגעות ליחידה כולה

- **(א) הוחלט: אין הנחות אינדוקציה שהחשבון משתמש בהן בלי שנראה.** החשבון השתמש קודם במה שבידינו, ובשלבים 9.2, 9.4, 9.5 ו־9.7–9.9 סגר את הצעד בעזרת הנחות האינדוקציה בלי שההנחה הוזכרה בהוכחה. הבקשה של מחבר הקורס: להשתמש בהנחה במפורש, ולא להחביא את השימוש בה מאחורי "חשבון פשוט". לכן, כמו ביחידה 8, החשבון בא בשני מהלכים: "נכונות המטרה נובעת מחשבון פשוט." מוכיח את המטרה לבדה, ו"נכונות המטרה נובעת מחשבון פשוט ומההנחות שבידינו." משתמש גם במה שבידינו, והבלוק אומר זאת. בכל שלב שבו ההנחה היא שוויון שהצד השמאלי שלו מופיע במטרה אחרי הפתיחה, מחליפים לפיה במפורש: length(l ++ m) ב־9.2, leaves(l) ו־leaves(r) ב־9.4, opening(φ) ו־opening(ψ) ב־9.7, atoms(φ) ו־atoms(ψ) ב־9.8–9.9; ב־9.7 שני הצדדים זהים אחרי ההחלפות, ולכן החשבון יצא מהארגז. רק ב־9.5 ההנחות הן אי־שוויונות, ואי אפשר להחליף לפיהן, ושם בצעד החשבון בעזרת ההנחות (כמו ב־8.8). המחיר: ב־9.9 שש החלפות נוספות (ראו שם). מה שנשאר פתוח: החשבון בעזרת ההנחות לא בודק שאי אפשר היה להחליף. ב־9.5 הוא בארגז, והסטודנט יכול להשתמש בו גם בבסיס; בשלבים האחרים של היחידה הוא לא בארגז.
- **(ב) מחרוזות, או עצים כלליים?** מחרוזות (Rosen: λ, ו־wx, האות x בסוף המחרוזת w) הן רשימות שנבנות מהצד השני, ולכן שלב עליהן יחזור על 9.1–9.3 בכתיב אחר; מספיק לומר בטקסט של 9.2 שזו הדוגמה של Rosen על מחרוזות. עצים כלליים (צומת עם רשימה של ילדים) דורשים אינדוקציה מקוננת: הנחת האינדוקציה היא על כל הילדים ברשימה, וההוכחה צריכה אינדוקציה נוספת על הרשימה. זה קשה, וגם ב־Lean `induction` לא מטפל ישירות בטיפוסים מקוננים כאלה. ההמלצה: לא, בשלב הזה. אם רוצים מבנה רביעי, עצים עם ערכים בצמתים, או ביטויים אריתמטיים (מספר, a + b, a · b) עם פונקציית ערך, קרובים יותר לחומר הקיים.
- **(ג) הנחת אינדוקציה חזקה יותר.** טענות כמו reverse עם צובר (revAppend(l, acc) = reverse(l) ++ acc) נכונות רק כשהנחת האינדוקציה היא "לכל acc": ∀acc (revAppend(l, acc) = reverse(l) ++ acc). זה הקושי הנפוץ ביותר באינדוקציה מבנית בקורסים של תכנות פונקציונלי, והוא מתחבר יפה ליחידה 4 (משתמשים בהנחה במהלך "לפי ה'לכל' … עבור העצם …"). הוא דורש: אפשרות בבלוק לבחור משתנים שנשארים כלליים (`induction l generalizing acc`), והצבה של ביטוי כמו a :: acc ב"לכל", כלומר הקלדה בשדה, אותה בעיה שבגללה הוחלף שלב 9.3. מחוץ לתחום כרגע; כדאי לשמור כשלב אפשרי אם תיפתר הקלדת ביטויים.
- **(ד) הרווח אחרי "ו־" בכותרת של הצעד.** הכותרת היא שורה של תוויות, עברית ונוסחאות בנפרד (תווית אחת שמערבבת אותן מצוירת משמאל לימין), ולכן "ו־" היא שדה נפרד ומופיעה עם רווח: "ו־ leaves(r) = nodes(r) + 1". אפשרויות: לכתוב "וגם" כמילה שלמה (אבל "וגם" הוא שם הקשר ∧ בקורס, ואולי מבלבל); לכתוב "נניח P(l), נניח P(r) ונוכיח P(node(l,r))"; להפריד בפסיק, כמו בחלונית מצב ההוכחה; או לצייר "ו־" והנוסחה בתווית אחת עם בידוד כיווניות, כמו בטקסטים של השלבים (`isolateFormulas`). ההצעה: "נניח P(l), נניח P(r)", שקריאה בלי שינוי בציור.
- **(ה) התפריט של פתיחת ההגדרה מציע פונקציות שעוד לא הוצגו.** התפריט מציע את כל הפונקציות של המבנה: length כבר ב־9.1, height ו־mirror כבר ב־9.4, atoms ו־binaries כבר ב־9.7, לפני הכרטיס שמגדיר אותן. אפשר להגביל את התפריט להגדרות שהוצגו עד השלב (`newDefinitions` של השלב ושל השלבים הקודמים), או להשאיר: פונקציה שלא מופיעה במטרה לא נפתחת, וההסבר אומר זאת.
- **(ו) הוחלט:** בלוק אינדוקציה אחד למספרים ולמבנים; שלושה מבנים בסדר של ספרי הלימוד (עם האסוציאטיביות במקום reverse ב־9.3); נוסחאות כעצמים נכתבות כפונקציות (ראו בתחילת המסמך).

## רקע: מה עושים מדריכים אחרים

- **Rosen, *Discrete Mathematics and Its Applications*.** בסעיף Recursive Definitions and Structural Induction קבוצות מוגדרות ב־basis step וב־recursive step, והאינדוקציה המבנית מוכיחה טענה על כל איברי הקבוצה באותה חלוקה: בסיס לכל איבר של ה־basis, וצעד לכל כלל של ה־recursive step. הדוגמאות שם: מחרוזות (Σ*), עם האורך של שרשור (המקבילה של 9.2); נוסחאות בנויות היטב, עם כל הקשרים (9.7–9.9); ועצים בינאריים מלאים, עם אי־שוויון בין מספר הצמתים לגובה (המקבילה של 9.5). גם הקשר בין העלים לצמתים הפנימיים בעץ בינארי מלא (9.4) מופיע אצלו, בפרק על עצים.
- **Enderton, *A Mathematical Introduction to Logic*.** כבר בפרק הראשון, על לוגיקת הפסוקים, הנוסחאות מוגדרות כקבוצה הקטנה ביותר שמכילה את הפסוקים וסגורה תחת פעולות הבנייה (אחת לכל קשר), ומזה נובע עקרון האינדוקציה: קבוצה של נוסחאות שמכילה את הפסוקים וסגורה תחת הפעולות מכילה את כל הנוסחאות. אחת הדוגמאות הראשונות היא הסוגריים המאוזנים (9.7). הפעולות אצל Enderton הן פונקציות על מחרוזות, וזה הרעיון שמאחורי הכתיב conj(φ,ψ) כאן.
- **Huth & Ryan, *Logic in Computer Science*.** בפרק 1, על לוגיקת הפסוקים, מוכיחים שהסוגריים בכל נוסחה מאוזנים, באינדוקציה (course-of-values) על הגובה של עץ הניתוח של הנוסחה. הנוסחאות שם הן עצי ניתוח, כמו בשלב 9.8.
- **Theorem Proving in Lean, Logic and Proof.** Logic and Proof מציג את המספרים הטבעיים כמבנה בנוי (הדגם של יחידה 8). ב־Theorem Proving in Lean רשימות ועצים הם טיפוסים אינדוקטיביים, כמו המספרים הטבעיים, והאינדוקציה עליהם נכתבת באותה צורה, עם חלק לכל דרך לבנות את המבנה. Theorem Proving in Lean, בפרק על טיפוסים אינדוקטיביים, מביא כתרגילים על רשימות את l ++ [] = l, את האסוציאטיביות של השרשור ואת האורך של שרשור (9.1–9.3). שם להנחת האינדוקציה יש שם; כאן אין לה שם (`_`), ומשתמשים בה לפי מה שהיא אומרת.
- **Software Foundations (Logical Foundations, הפרק על רשימות).** אותם תרגילים על רשימות (השרשור עם רשימה ריקה, אסוציאטיביות, האורך של שרשור), ואחריהם reverse והטענה ש־reverse(reverse(l)) = l, שהיא המקבילה של 9.6 ברשימות; שם היא דורשת טענת עזר שהוכחה קודם.
- **Natural Number Game.** הדגם של יחידה 8, ודרכה של היחידה הזאת: כל צעד הוא פתיחת הגדרה או החלפה לפי הנחת האינדוקציה, והחשבון לא פותח הגדרות. 9.1 מקביל ל־0 + n = n, ו־9.3 לקיבוץ של החיבור.
- **טעויות נפוצות:**
  - אינדוקציה על המשתנה הלא נכון, זה שההגדרות לא מפרקות. ממנה נולד שלב 9.2.
  - שימוש בהנחת האינדוקציה לפני שפותחים את ההגדרה: ההנחה מדברת על l, והמטרה על a :: l. ממנה נולד שלב 9.3.
  - שכחה של אחת משתי הנחות האינדוקציה בצעד של עצים, או שימוש בהנחה של φ במקום של ψ. הכותרת של הצעד כותבת את שתיהן (9.4–9.6).
  - שכחה של מקרה (למשל הצעד של ¬). כאן אי אפשר לשכוח: הבלוק פותח חלק לכל דרך.
